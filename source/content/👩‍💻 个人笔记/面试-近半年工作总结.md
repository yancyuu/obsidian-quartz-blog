# 📋 近半年工作与项目总结（面试用）

> 主线：**企业级 AI Agent 平台 + 垂直应用 + 知识库基础设施**。从「平台 → 检索底座 → 业务 Agent → 整体架构」全链路自研。

## 🎯 个人定位

## 🚀 项目一：AgentCli + AgentBus · AI 数字员工平台（主力）

**一句话**：本地优先的 AI 数字员工工作台——「**CLI for agents, Web for humans**」，像管理真实团队一样管理 AI Agent。

### 解决的问题

- AI Agent 越来越多，**谁在做什么、进展如何** 没有统一视图
- 多种运行时（Claude Code / Codex / Cursor）各自独立，**无法协调管理与统一计量**
- 团队 AI 使用缺乏**可见性、归因、审计**

### 产品形态（双产品）

| 产品         | 定位                                                              | 场景                                  |
| ------------ | ----------------------------------------------------------------- | ------------------------------------- |
| **AgentCli** | 本地 CLI + Web 工作台，自动采集多运行时用量、统一管理数字员工团队 | 单机 / 脚本化 / 本地团队              |
| **AgentBus** | 中心化数据总线，把单机工具升级成企业平台                          | 多人协作 / IM 触发任务 / 企业用量看板 |

> 关系：AgentCli 是本地操作面，AgentBus 是协调骨干。不接 Bus 是完整单机，接入解锁企业能力。

### 我做的（主力开发，近半年 400+ 提交，迭代至 v1.9.x）

- 数字员工**创建 / 授权 / 运行时 CLI** 全流程
- **Web 工作台**：团队组建、任务分配、进度追踪、交付审核
- **多运行时用量采集**：Claude Code / Codex / Cursor 统一计量与上报
- **CLI 机器可读输出**：所有命令支持 `--json`，供 agent / 自动化调用
- **跨平台分发**：一行安装（自带 Node 运行时，no-Node）、standalone 便携包、npm 发布（`@yancyyu/agentcli`）
- **CI/CD release 流水线**、预编译加速（**冷启动 28x faster**）

### 技术难点（面试可深讲）

1. **多运行时统一计量**：不同 Agent 运行时（Claude Code/Codex/Cursor）用量口径不一，如何归一化采集、归因到数字员工/团队
2. **跨平台一键安装**：Windows/macOS/Linux 无环境依赖安装（走 GitHub 镜像解决国内网络）、预编译 server+worker 提速
3. **本地优先 vs 企业协作的双模架构**：单机完整可用 + 可平滑接入 AgentBus 升级企业级

## 🚀 项目二：customer-agent · 智能客服 Agent

**一句话**：基于异步 Python 的 AI 客服服务，RAG 增强 + Agent 能力，服务于 SKG 健康科技。

### 技术架构

| 层       | 选型                                           |
| -------- | ---------------------------------------------- |
| Web 框架 | **Sanic 25.x**（异步优先，全链路 async/await） |
| 向量库   | **Qdrant**（RAG 检索）                         |
| AI 框架  | **Pydantic AI**（类型安全 + Agent 能力）       |
| 存储     | PostgreSQL 14+ / Redis 7+                      |
| 核心     | RAG：向量检索 + LLM 生成                       |

### 我做的（核心开发，264 提交）

- 异步全链路客服服务（高并发 IO）
- RAG 增强：知识向量检索 + LLM 生成回答
- Pydantic AI 驱动的 Agent 客服能力

### 技术难点 + 成效（面试重点）

- **召回准确率调优**：chunking 策略、向量检索 + 关键词混合、rerank
- **幻觉控制**：强约束 Prompt + 引用溯源
- **成效**：用 RAG 重构了原有低效客服方案（具体降本见文末分析）

## 🚀 项目三：ikb-retriever-service · 企业知识库检索服务

**一句话**：企业知识库的**数据层 + 检索层**基础设施，作为上层 RAG/AI 应用的底座，并可作为 **MCP 工具服务**。

### 定位（重要边界）

- ✅ 知识库 CRUD + 文件管理 + 权限
- ✅ 多格式文档解析（PDF / DOCX / TXT / MD）
- ✅ 向量化存储（**Milvus**）
- ✅ 多维检索：结构化 + 全文 + 向量相似度
- ✅ 可作为 **MCP（Model Context Protocol）工具服务** 给 Agent 调用
- ❌ 不含 AI 回答生成（纯检索底座，与上层 RAG 问答解耦）

### 价值

把「文档→向量→检索」做成**可复用底座**：客服 Agent、产品 Agent 等都基于它，避免每个应用重复造检索轮子；MCP 化让任何 Agent 都能工具化接入知识库。

### 技术难点

- 多格式文档解析的鲁棒性
- 向量化 + 存储的规模化（Milvus）
- 检索精度（向量 + 全文混合）与 MCP 工具接口设计

## 🏗️ 项目五：AI Agent 系统整体架构设计

**一句话**：企业级 AI Agent 的整体架构方案（领域驱动单体 + 弹性分布式）。

### 架构要点

- **领域驱动单体 + 弹性分布式部署**：快速验证业务价值 + 保持可演进性
- 选型理由：GPU 计算并发 + 物理链路并发差异巨大，传统微服务治理成本高，单体快速迭代更合适
- 分层：应用网关（API 网关 + 鉴权）→ Agent 网关 → Agent 运行时（管理 Agent / 产品 Agent）→ 工具适配层 + 模型层（LLM / LMA / ASR）
- 配套方案：智能客服 2.0、电商链接智能巡检、产品/Boss/VOC Agent 等多个垂直方案

## 📊 降本/成效分析（数据怎么算的）

> ⚠️ 面试讲「降本」必须能拆解维度。以下是客服 RAG 重构的**降本计算逻辑**（实际数字请按你的真实情况填/校准）：

### 客服场景降本构成（RAG Agent 替代原方案）

| 降本维度           | 计算逻辑                                   | 说明                                             |
| ------------------ | ------------------------------------------ | ------------------------------------------------ |
| **① 人力替代**     | (原人工客服坐席数 − 现坐席数) × 人均年薪   | RAG Agent 自动处理掉大部分高频问题，坐席需求下降 |
| **② 方案替代**     | 原外部/采购方案年费 − 自研 RAG 运维成本    | 替代昂贵的外部采购方案                           |
| **③ 单次会话成本** | 原单次服务成本 − RAG 单次成本（推理+检索） | RAG 单次成本远低于人工                           |
| **④ 运维/开发**    | 原方案运维人力 − 自研自动化运维            | 自动化降低长期运维                               |

**怎么算出一个百分比**：选一个基准（如原方案年度总成本 T），降本 = (T − 新方案年度总成本) / T。

**面试讲法建议**：「降本主要来自三层：① RAG 替代了 X% 的人工高频咨询；② 自研替代了原采购方案；③ 异步架构 + 检索优化压低了单次成本。综合下来年度成本降到原来的 1/N。」——用**维度 + 倍数/比例**比硬背 85% 更可信。

### 平台层（agentcli）成效维度

- 多运行时统一计量 → AI 用量**可见、可归因、可审计**（治理价值）
- 跨平台一键安装 + 预编译 28x 加速 → **部署/冷启动效率**
- CLI+Web 双模 → agent 自动化 + 人管理兼顾
