### 第一阶段：理解“黑盒”的构造（Tokenizer & Transformer）

**目标：** 彻底理解模型是如何“看”和“写”的，解决 Token 计费优化、格式错误、字符数不对等问题。

- **核心概念：** BPE 算法、Embedding 空间、Masked Self-Attention。
    
- **实操任务：**
    
    1. **Tokenizer 实验：** 使用 `tiktoken` (OpenAI) 或 `transformers` 库，对比同一个句子在不同模型（如 GPT-4 vs Llama-3）下生成的 Token ID。观察特殊字符（如换行符、中文）的差异。
        
    2. **Attention 矩阵可视化：** 使用 Jupyter Notebook 运行一个简单的 BERT 或 GPT 演示，手动打印出某一层 Attention 的权重矩阵，直观感受模型在关注哪些词。
        
- **推荐资源：**
    
    - [Andrej Karpathy: Let's build GPT from scratch](https://github.com/karpathy/ng-video-lecture) (代码极其优雅，必看)。
    - [The Illustrated Transformer](https://jalammar.github.io/illustrated-transformer/) (公认最好的图解)。

### 第二阶段：算清“性能账”（KV Cache & 推理优化）

**目标：** 解决 Agent 在生产环境中的高延迟、并发性能瓶颈和显存溢出（OOM）问题。
- **核心概念：** Prefill vs Decoding、KV Cache 显存占用公式、PagedAttention、量化（GPTQ/AWQ）。
- **实操任务：**
    1. **显存预算推演：** 尝试手动计算：一个 7B FP16 模型，在 100 并发、Context 长度 4K 的情况下，需要多少张 A100 显卡？
    2. **压测实验：** 使用 `vLLM` 部署一个模型，分别测试开启和关闭 `chunked-prefill` 时的首字延迟（TTFT）。
        
- **推荐资源：**
    
    - [vLLM 官方文档/博客](https://blog.vllm.ai/)：重点看其如何优化 PagedAttention。
    - [Transformer Inference Arithmetic](https://kipp.ly/transformer-inference-arithmetic/)：这是架构师必读的“算账指南”。

### 第三阶段：定制化“大脑”（SFT & LoRA 微调）
**目标：** 掌握什么时候该用 RAG，什么时候该用微调，并具备自主训练模型遵循特定 Agent 协议的能力。
- **核心概念：** SFT（指令微调）、LoRA/QLoRA 原理、Chat Template (如 Jinja2)。
- **实操任务：**
    1. **微调一个格式化专家：** 使用 [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory) 框架，准备 100 条你的业务数据，用 LoRA 微调一个 1B 或 3B 的小模型，让它输出极其严格的 JSON 格式。
    2. **对比实验：** 比较微调后的模型与“Prompt 引导的 Base 模型”在处理复杂工具调用时的成功率。
        
- **推荐资源：**
    - [LLaMA-Factory GitHub](https://github.com/hiyouga/LLaMA-Factory)：国产神库，全中文文档，非常适合快速上手。
    - [Hugging Face: Fine-tuning a model with LoRA](https://huggingface.co/docs/peft/index)。

### 第四阶段：前沿推理与评估（CoT & Evaluation）

**目标：** 理解 o1、DeepSeek-R1 这种推理模型背后的原理，构建 Agent 的自动化评估体系。
- **核心概念：** Chain-of-Thought (CoT)、Logits 概率分布、LLM-as-a-Judge。
- **实操任务：**
    1. **Logits 分析：** 调用 OpenAI 或 DeepSeek 的 API，开启 `logprobs` 参数，观察模型在回答问题时，前几个候选 Token 的概率分布，以此判断模型的“困惑度”。
    2. **构建 Eval 流水线：** 编写一个脚本，利用 GPT-4o 作为裁判，自动给你的 Agent 表现打分。
        
- **推荐资源：**
    - [DeepSeek-V3/R1 Tech Report](https://github.com/deepseek-ai/DeepSeek-V3)：即使看不懂公式，也要看其架构设计部分。

## 🛠 架构师必备的数学公式（仅此一个）

作为架构师，你只需要在脑子里刻下这个关于显存的估算公式，就能在开会时瞬间判断方案可行性：

$$VRAM \approx \Phi \times 2 \times \text{Quant\_Factor} + \text{KV\_Cache}$$

- $\Phi$：参数量（如 7B）。
- $2$：16位浮点数占 2 字节。
- $\text{Quant\_Factor}$：量化比例（如 4-bit 为 0.25）。
