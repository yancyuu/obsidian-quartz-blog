# 确定性边界

## 定义
确定性边界是 Agent 架构重构的核心方法论，指在企业级 Agent 系统中明确划分**确定性逻辑**与**概率性生成**之间的分界线。具体而言，它要求架构师识别出业务流程中哪些环节必须由状态机（FSM）、规则引擎等确定性组件严格控制，哪些环节可以安全地交给 LLM 进行开放性推理与创意生成。这一方法论体现了「在灵活性与可控性之间寻找平衡」的工程思想，是降低 Agent 系统运行成本和提升稳定性与可控性的关键前提。

## 关键特征
- **二分性**：将系统中的每个环节划分为「确定性控制」或「概率性发挥」两类，边界清晰，避免灰色地带。
- **业务逻辑优先剥离**：强业务逻辑（如退款审核、身份验证、订单状态流转）被强制剥离出 LLM，交由 FSM 或规则引擎处理，从根源上消除 LLM 的不确定性带来的风险。
- **成本与稳定性双驱动**：确定性逻辑不消耗 Token，运行成本极低且行为可预测；将高成本的 LLM 调用聚焦于真正需要语义理解和创造性推理的环节，从而同时实现降本与提效。
- **架构设计的起点**：该方法论建议在 Agent 系统架构设计之初，优先进行确定性边界梳理，以此为基础规划后续的组件选型与流程编排。

## 应用
- **企业级客服系统**：在 [[entities/客服agent|客服Agent]] 中，将退款审核、身份验证、订单查询等强业务流程交由有限状态机处理，将闲聊、意图澄清、复杂情感安抚等开放性任务留给 LLM。
- **RAG 系统架构选型**：在 Agentic RAG 架构中，通过明确确定性边界来决定路由策略、检索触发条件和生成兜底逻辑的控制权归属，防止 LLM 产生幻觉或随意触发昂贵的检索链路。
- **意图识别与模型路由**：通过边界梳理，确定意图识别等关键判定环节是依赖确定性的分类模型，还是依赖 LLM 的零样本推理，以此优化系统的整体响应延迟和运行成本。
