# 混合工具路由

## 定义
混合工具路由是一种工程化工具调度策略，核心思想是根据业务场景的差异采用不同的工具注册与路由方式：在业务紧耦合、上下文依赖强的核心任务链上使用原生工具路由机制，而在跨域集成和轻交互场景中使用 MCP（Model Context Protocol）格式注册。该策略兼顾了性能稳定性与未来演化空间，避免 MCP 协议在垂直业务系统中引入过度抽象和上下文缺失问题。文章建议将热点工具服务注册为 MCP-Service，其余保留本地函数形态。

## 关键特征
- **场景分层路由**：根据上下文依赖强度和业务耦合度将工具调用场景划分为核心任务链与跨域轻交互两类，分别采用不同路由机制
- **核心链路保稳**：在高频、紧耦合的核心业务路径上坚持原生工具路由，保障性能与上下文一致性
- **边缘链路开放**：在跨域集成和轻交互场景中使用 MCP 格式注册，保留系统未来的扩展和演化能力
- **避免过度抽象**：防止 MCP 协议的通用性在垂直业务系统中引入不必要的抽象层，导致上下文信息丢失
- **热点工具服务化**：将高频调用的热点工具注册为独立的 MCP-Service，其余工具保持本地函数形态，实现轻量化的服务化治理

## 应用
- **企业级智能体系统**：在核心业务流程中使用原生路由保证稳定运行，同时通过 MCP 接口对外开放能力
- **多团队协作平台**：各团队内部使用原生工具链路，跨团队协作通过 MCP-Service 进行标准化对接
- **渐进式架构演进**：在已有原生工具体系中逐步引入 MCP 协议，以混合路由方式实现平滑过渡，而非一次性全量迁移
