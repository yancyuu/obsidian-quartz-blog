# IO密集与CPU密集的区分

## 定义
IO 密集型任务和 CPU 密集型任务是两种根本不同的工作负载类型，需要采用不同的并发策略。在并发模型选型中，这一区分构成了核心决策依据：IO 密集且大量连接适用 asyncio 协程（单线程高并发），IO 密集且少量连接适用多线程，CPU 密集则适用多进程（真并行）。

## 关键特征
- **工作负载本质不同**：IO 密集型任务的瓶颈在于等待外部操作（网络、磁盘等）完成，CPU 大部分时间处于空闲状态；CPU 密集型任务的瓶颈在于计算能力，CPU 持续满载运行。
- **并发策略不同**：IO 密集型任务适合利用协程或线程在等待期间切换执行其他任务；CPU 密集型任务受限于 [[concepts/gil|GIL]]，需要使用多进程才能实现真正的并行计算。
- **连接规模影响选型**：同样是 IO 密集型任务，大量连接场景适合 asyncio 协程实现单线程高并发，少量连接场景则多线程即可胜任。
- **决策可图化**：该区分可以通过决策图清晰表达，以任务类型为入口，根据工作负载特征导向不同的并发方案。

## 应用
- **高并发网络服务**：如 Web 服务器、API 网关等面临大量网络连接的 IO 密集场景，采用 asyncio 协程实现单线程高并发。
- **数据处理与计算**：如图像处理、科学计算等 CPU 密集场景，采用 multiprocessing 多进程实现真并行。
- **轻量级 IO 任务**：如文件读写、数据库查询等少量连接的 IO 密集场景，采用多线程模型即可。
- **混合负载系统**：实际系统中往往需要根据任务类型组合使用多种并发模型，如协程处理 IO、多进程处理 CPU 密集计算。
