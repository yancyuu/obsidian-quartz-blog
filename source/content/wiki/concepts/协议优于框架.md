# 协议优于框架

## 定义
协议优于框架是"可逃逸架构"的第二大设计原则，核心思想是：在代码架构中，应遵循开放标准协议而非绑定特定框架。代码中严禁充斥框架特有的对象，工具层必须封装为标准的 MCP（Model Context Protocol）或 OpenAPI 接口，从而拒绝框架锁定，确保技术栈之间的低切换成本。

## 关键特征
- **拒绝框架锁定**：代码中严禁充斥框架特有的对象，避免业务逻辑与框架深度耦合。
- **标准化接口封装**：工具层必须封装为标准协议接口（如 MCP 或 OpenAPI），而非直接依赖框架的私有 API。
- **低切换成本**：遵循标准协议后，切换底层框架（如从 LangChain 切换到原生代码）时，工具层代码无需重写。
- **协议驱动**：以开放协议作为模块间通信契约，取代框架内部的数据结构与调用约定。

## 应用
- **Agent 工具层设计**：将 Agent 调用的外部工具封装为 MCP 标准接口，使得 Agent 框架可以随时替换而不影响工具层。
- **技术栈迁移**：当团队决定从某一框架（如 LangChain）迁移到另一框架或原生实现时，只需替换编排层，工具和数据接口层保持不动。
- **多框架协作**：不同框架实现的系统组件可以通过标准协议（如 OpenAPI）进行互操作，避免单一框架锁定整个系统。
