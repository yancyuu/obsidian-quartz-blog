# 函数与工具区分

## 定义
函数与工具区分是 MCP 服务架构中的代码整洁度考核标准。该标准明确区分了「函数」（如 `string_split`）和「工具」（如 `check_inventory`）：函数是实现细节，禁止暴露给 AI；工具代表业务意图，必须封装为 MCP 接口。这一区分原则确保 AI 只接触到有业务语义的操作接口，避免被底层技术细节干扰，同时也是实现 Client-Server 物理隔离的基础。

## 关键特征
- **语义边界清晰**：函数属于技术实现层面的底层操作（如字符串拆分），工具属于业务意图层面的高层操作（如库存检查），两者通过语义层级严格划分。
- **AI 可见性控制**：函数被严格禁止暴露给 AI 模型，只有封装为 MCP 接口的工具才对 AI 可见、可调用。
- **业务意图封装**：工具必须承载明确的业务语义，而非单纯的技术操作，确保 AI 的每次调用都对应一个有意义的业务动作。
- **架构隔离基础**：函数与工具的区分是实现 Client-Server 物理隔离的前提条件，为可逃逸架构提供接口层面的规范支撑。

## 应用
- **MCP 服务设计**：在设计 MCP（Model Context Protocol）工具接口时，开发者需评估每个操作的业务语义强度，仅将具备业务意图的操作封装为工具暴露给 AI。
- **代码审查标准**：作为团队代码整洁度的考核维度，在 Code Review 中检查是否存在将底层函数误暴露为 MCP 工具的情况。
- **AI Agent 架构治理**：在企业级 Agent 落地过程中，用该标准约束工具层的粒度和范围，防止 AI 上下文被大量无意义的技术函数污染。
