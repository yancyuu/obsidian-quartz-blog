# 业务闭环

## 定义
业务闭环是一种 Agent 架构设计方法，强调每个 Agent 都应当包含自己独立的 Prompt、Tool 和 Logic，形成完整的、可独立运行的业务单元。在代码结构上，每个 Agent 目录下包含 `agent.py`（核心逻辑）、`tools.py`（工具绑定）、`prompts.py`（专用 Prompt）和 `tests`（专用测试），从而构成从定义到验证的完整业务闭环。

## 关键特征
- **职责单一性**：每个 Agent 聚焦于一个明确的业务目标，避免承担过多职责
- **结构一致性**：统一的目录结构（agent.py / tools.py / prompts.py / tests），降低认知负担
- **逻辑独立性**：Agent 内部的 Prompt、Tool 和 Logic 自包含，不依赖外部 Agent 的内部实现
- **可维护性**：修改某个 Agent 的行为不会波及其他 Agent，变更影响范围可控
- **可测试性**：每个 Agent 拥有专用测试目录，支持独立验证业务逻辑的正确性
- **低耦合**：Agent 之间通过明确定义的接口交互，避免深层的逻辑耦合

## 应用
- **Agent 应用开发**：在构建多 Agent 系统时，以业务闭环为单位划分 Agent 边界，每个 Agent 目录即为一个可独立开发、测试和部署的模块
- **团队协作开发**：不同开发者或团队可并行开发各自负责的 Agent，互不干扰
- **Agent 迭代演进**：单个 Agent 的 Prompt 优化、工具增减和逻辑调整均在自身闭环内完成，不影响整体系统稳定性
- **代码审查与质量管控**：以业务闭环为粒度进行 Code Review，确保每个 Agent 的 Prompt、Tool 和 Logic 符合规范
