# 不答策略

## 定义
不答策略是作者在 [[entities/信仰咨询agent|信仰咨询agent]] 中引入的安全兜底机制，核心是设计"拒答 / 澄清 / 转人工"三段式的降级处理路径。当 Agent 遇到敏感话题或超出能力边界的问题时，不应强行回答，而应根据风险等级依次执行：直接拒答、向用户澄清歧义、或转交人工处理。该策略配合双层白名单一起使用，将风险管理前置到 LLM 决策之前，确保 Agent 在禁区外活动。作者强调这是 Agent 安全防护的最关键一环，必须在上线前明确且可触发。

## 关键特征
- **三段式降级路径**：按风险等级依次执行"拒答 → 澄清 → 转人工"，形成逐级兜底的处理链条。
- **风险前置**：将风险管理放在 LLM 做出回答决策之前，而非事后补救。
- **必须明确且可触发**：兜底路径在上线前就需定义清晰，并确保在实际运行中可以被真正触发执行。
- **与白名单配合使用**：搭配双层白名单机制，划定 Agent 的活动边界，确保其在安全区域内运行。
- **安全防护核心环节**：作者将其定位为 Agent 安全防护体系中最关键的一环。

## 应用
- **信仰咨询场景**：在涉及宗教、信仰等高度敏感话题时，通过不答策略避免 Agent 产生不当言论。
- **敏感话题过滤**：对超出 Agent 能力边界或涉及高风险的问题执行拒答或转人工处理。
- **Agent 上线前安全审查**：作为上线 checklist 的必选项，确保兜底路径已配置且可触发。
- **企业级 Agent 部署**：在面向用户的 Agent 系统中作为标准安全机制嵌入。
