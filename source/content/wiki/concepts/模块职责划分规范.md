# 模块职责划分规范

## 定义
本规范定义了一套严格的后端项目分层架构，将代码划分为 `services`（路由层）、`controller`（控制器层）、`models`（ORM 模型层）、`scheme`（数据结构层）等多个职责分明的模块。每一层各司其职：`services` 层仅负责 HTTP 请求处理和路由转发，严禁写入业务逻辑或 SQL；`controller` 层只关心业务输入到业务输出的转换；`models` 层专门定义数据结构。这种分层确保了单一职责原则的贯彻，同时支持跨协议复用业务逻辑。

## 关键特征
- **职责严格隔离**：`services` 层只做请求接入，`controller` 层只做业务逻辑，`models` 层只定义数据结构。
- **禁止层级越权**：严禁在 `services` 中直接写业务逻辑或 SQL，保证路由层轻量化。
- **输入输出标准化**：`Controller` 层只关心“接受纯 Python 参数 → 执行业务 → 返回纯 Python 结构”，不与具体的协议绑定。
- **数据结构解析独立**：通过 `scheme` 层独立管理数据结构的解析与校验，使其不与控制器逻辑耦合。
- **支持跨协议复用**：业务逻辑集中于控制器层且仅依赖纯 Python 参数，可无缝适配 HTTP、WebSocket 或 RPC 等不同通信协议。

## 应用
- **后端 API 开发**：为 Web 服务（如 FastAPI / Flask 等）提供清晰的工程目录规范，指导团队协同开发。
- **跨协议系统适配**：在 HTTP 接口之外的 gRPC 或 WebSocket 通信场景下，通过复用控制器层的逻辑实现开发效率最大化。
- **大型工程代码审查**：作为 Code Review 时的架构约束准则，防止开发者在路由层或 ORM 层堆积业务逻辑代码。
