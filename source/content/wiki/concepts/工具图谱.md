# 工具图谱

## 定义
工具图谱是一种 Agent 设计方法，强调在设计 Agent 时从"有哪些动作可以调用"出发，而非从 Prompt 出发。其核心理念是：Agent 的关键能力来自工具调用而非 LLM 本身。设计者应在早期就梳理并绘制出完整的工具图谱，涵盖 API、插件、检索器、多模态输入等各类可调用工具，以此界定 Agent 的能力边界。

## 关键特征
- **动作优先**：设计起点是"有哪些动作可以调"，而非 Prompt 工程，工具定义先于对话逻辑。
- **能力源自工具**：Agent 的实际能力取决于可调用的工具集合，而非 LLM 自身的推理能力。
- **全谱覆盖**：工具图谱应包括 API、插件、检索器、多模态输入等多种工具类型，构建完整的能力地图。
- **粒度适中**：工具粒度需要合理把控，如搜索、选项选择、数据库查询、文件上传等，避免过粗或过细。
- **能力边界界定**：工具图谱直接决定 Agent 能做什么、不能做什么，是 Agent 能力边界的决定性因素。

## 应用
- **Agent 初始设计阶段**：在编写任何 Prompt 之前，先梳理业务场景中需要的所有动作，画出完整的工具图谱。
- **能力评估与规划**：通过审视工具图谱的完整度，评估 Agent 能否覆盖目标场景的所有操作需求。
- **迭代优化**：根据实际使用反馈，持续调整工具粒度和新增工具，扩展 Agent 的能力边界。
- **团队协作**：工具图谱作为设计文档，帮助团队成员对 Agent 能力形成统一认知。
