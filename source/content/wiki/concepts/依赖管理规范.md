# 依赖管理规范

## 定义
该规范规定了使用 Poetry 管理项目依赖的标准流程，所有包版本固定在 `pyproject.toml` 中。`ai_sdk` 和 `common_sdk` 作为独立 SDK 分别管理各自的 `pyproject.toml` 依赖。Docker 构建采用两阶段方式：先使用 Poetry 导出完整的 `requirements.txt`，再用 pip 安装依赖，以获得更轻量的运行时镜像。Dockerfile 配置保持统一，仅项目名称不同。

## 关键特征
- 所有包版本严格固定在 `pyproject.toml` 文件中，确保环境一致性
- 使用 Poetry 作为统一的依赖管理工具
- `ai_sdk` 和 `common_sdk` 各自独立维护 `pyproject.toml`，互不干扰
- Docker 构建采用两阶段策略：Poetry 导出 `requirements.txt` + pip 安装
- Dockerfile 配置统一，仅项目名称不同

## 应用
- **项目初始化**：新建项目时使用 Poetry 创建 `pyproject.toml` 并锁定所有依赖版本
- **SDK 依赖更新**：修改 `ai_sdk` 或 `common_sdk` 的依赖时，分别在各自的 `pyproject.toml` 中操作
- **Docker 镜像构建**：构建阶段先用 Poetry 导出 `requirements.txt`，运行阶段仅用 pip 安装所需依赖，生成轻量级生产镜像
