# 进程调度

## 定义
进程调度（Process Scheduling）在本文语境中特指 Agent 开发者需要处理的 Skill 优先级管理问题——即当多个 Skill 同时可用时，决定哪个 Skill 应该被优先加载执行。作者将此列为 Agent 开发者被迫承担的操作系统级职责之一，与内存管理和 I/O 阻塞处理并列，反映了当前 Agent 架构将底层资源管理负担转嫁给开发者的现状。

## 关键特征
- **Skill 优先级裁决**：开发者需要为多个 Skills 设定优先级，决定哪个 Skill 在运行时获得先执行权
- **操作系统级职责的转嫁**：本应由底层框架或运行时自动管理的调度逻辑，被迫由上层应用开发者手动实现
- **与资源管理问题的耦合性**：与内存管理（上下文窗口分配）、I/O 阻塞处理共同构成 Agent 开发者的三大底层负担
- **手动决策的脆弱性**：依赖开发者经验进行调度决策，缺乏系统级的自动优化机制

## 应用
- 当 Agent 挂载大量 Skills 时，开发者需要设计优先级策略以决定哪个 Skill 优先加载到有限的上下文窗口中
- 在多任务 Agent 场景下，管理不同功能模块的执行顺序和资源争用
- Agent 架构设计中，评估是否需要引入系统级的调度器来替代开发者的手动管理
