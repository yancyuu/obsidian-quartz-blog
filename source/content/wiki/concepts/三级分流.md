# 三级分流

## 定义

三级分流是一种 Agentic RAG 系统的分层架构设计方法，核心思想是将请求按复杂度路由到不同处理层级。该方法将处理流程划分为三个层级：L1（路由层）负责请求分流，L2（执行层）处理具体任务，L3（管控层）通过规则引擎或有限状态机（FSM）进行约束。其根本目标是将确定性的业务逻辑从 LLM 推理中剥离，交由传统工程手段处理，从而降低运行成本并控制系统风险。

## 关键特征

- **分层架构**：采用 L1（路由）、L2（执行）、L3（管控）三层结构，各层职责明确、解耦运行。
- **逻辑剥离**：将确定性的业务逻辑从 LLM 推理中剥离，交给规则引擎或状态机处理，减少对大模型生成的依赖。
- **成本控制**：通过精准路由避免所有请求都走最昂贵的模型路径，是企业级 Agent 降本的核心手段。
- **风险约束**：利用 L3 管控层对 Agent 行为进行边界约束，防止 LLM 生成不可控结果。
- **与状态机结合**：通常与"状态机管控"配套使用，形成完整的 Agentic RAG 治理架构。

## 应用

- **企业级客服系统**：在高并发客服场景中，将简单查询路由至轻量级模型或知识库检索，复杂对话才调用大模型。
- **智能问答 Agent**：对不同复杂度的用户问题进行分层处理，优化响应速度和资源消耗。
- **RAG 系统架构重构**：作为系统从原型向企业级生产环境演进时的核心架构选型方案。
