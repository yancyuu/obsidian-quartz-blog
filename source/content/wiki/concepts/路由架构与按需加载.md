## Description
L1 Router 负责意图识别与路由分发，L2 Worker（Task Executor）作为 Agent 运行时的第二层组件，负责具体任务的执行。在 L1 Router 完成意图识别后，L2 Worker 根据匹配结果激活特定技能（如查库存），通过协议层动态建立连接（On-Demand），并按需加载该领域下的 MCP Tools 来完成工具调用与任务执行。整个工作流程从步骤3（激活特定技能）到步骤5（调用工具 JSON Schema），均体现了[[concepts/渐进式披露|渐进式披露]]的设计理念——按需暴露能力，降低上下文消耗。该原则以「8k 挑战」作为硬性验证标准，严禁将 ERP、CRM、OA 等 50+ 个工具一次性注入 System Prompt，规避长窗口模型的强依赖。

按需加载（On-Demand）是该架构中工具调用的核心策略，在工作流程的第4步「动态建立连接」中得以体现——Agent 运行时在识别用户意图后，才根据匹配的技能动态建立与对应工具的连接，而非预先加载所有可用工具。这种设计依赖协议层（[[concepts/协议优于框架|协议优于框架]]）的支持，通过 [[entities/MCP|MCP]] / OpenAPI Standard 等标准化接口实现工具的即插即用。按需加载与[[concepts/无状态上下文|无状态上下文]]（Stateless Context）紧密关联——运行时按需加载工具而非在初始化阶段全量注入，是实现无状态运行时的关键机制，有效降低了上下文窗口的压力。

该机制的轻量级特性进一步依赖于 [[concepts/skill-registry|Skill Registry]] 的设计：注册表中仅存储技能名称，不包含完整的工具定义。配合[[concepts/on-demand-connection|按需建立连接]]（On-Demand）的策略，Agent 得以在运行时才拉取工具描述并建立连接，从而实现了真正意义上的轻量级工具调用流程——这与传统的预加载所有工具方式形成鲜明对比，避免了工具描述间的互相干扰。
