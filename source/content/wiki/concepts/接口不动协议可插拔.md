## Description
这一设计方法的核心思想是**接口契约稳定，底层实现可替换**。在传统 Web 后端中，它要求路由层将请求解析、Controller 调用与结果返回三步与数据格式完全解耦，新增协议时只需在 `service/` 下创建子目录（如 `service/ws/`、`service/proto/`），复用现有 Controller，无需修改业务逻辑。系统可以从单一的 JSON over HTTP 起步，按需平滑迁移到 Protobuf-over-HTTP 或全面切换到 gRPC。在 Agent 架构中，该思想进一步体现为「可逃逸设计」：工具的具体实现集中在 `modules` 通用功能模块中，而 `core-agent` 只引用工具的 Schema 定义，不直接依赖实现细节。这种解耦方式使得 Agent 可以在不修改自身代码的情况下替换底层工具实现，是保证系统渐进式演进和长期可维护性的关键。
