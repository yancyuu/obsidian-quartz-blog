# 接口不动、协议可插拔

## 定义
这是一种架构设计方法，要求在路由层（Services）将请求体解析、调用 Controller、返回结果这三步与具体的数据传输格式（如 JSON、Protobuf）完全解耦。当需要引入 WebSocket、RESTful 或 gRPC 等新协议时，只需在服务层新建对应目录，复用现有 Controller，从而保证核心业务逻辑的稳定性。

## 关键特征
- **路由层与数据格式解耦**：请求体解析 → 调用 Controller → 返回结果这三步不绑定任何特定的数据传输格式（JSON、Protobuf 等）。
- **Controller 高度复用**：不同协议（WebSocket、RESTful、gRPC）共享同一套 Controller 和业务逻辑，无需为每种协议重写核心代码。
- **协议扩展零侵入**：新增协议时只需在 `service/` 下创建新的子目录（如 `service/ws/`、`service/proto/`），不修改任何已有业务逻辑。
- **渐进式演进**：系统可以从单一的 JSON over HTTP 起步，按需平滑迁移到 Protobuf-over-HTTP 或全面切换到 gRPC。

## 应用
- **Web 后端服务**：初期仅提供 RESTful JSON API，后续根据实时通信需求无缝接入 WebSocket。
- **微服务架构**：内部服务间通信从 HTTP/JSON 升级为 gRPC/Protobuf，以提升传输效率和降低延迟。
- **API 网关接入**：在不改动核心业务逻辑的前提下，快速适配 API Gateway 层的多协议转换需求。
