# On-Demand Connection

## 定义

On-Demand Connection（按需连接）是该架构中工具调用的核心连接策略。当 L1 Router 完成意图匹配并激活特定技能后，系统才动态建立与对应能力服务（如库存服务、CRM 服务）的连接。这种方式避免了维持大量常驻连接的资源开销，同时确保了隔离性——每个请求的连接是独立且短暂的。On-Demand Connection 是实现无状态上下文和可逃逸架构的关键支撑机制。

## 关键特征

- **延迟初始化**：连接不在系统启动时预建，而是在 L1 Router 完成意图匹配、激活特定技能后才动态建立，遵循按需加载原则。
- **请求级隔离**：每个请求的连接是独立且短暂的，不同请求之间不共享连接状态，天然具备隔离性。
- **资源高效**：避免了维持大量常驻连接的资源开销（如内存、线程池、网络套接字等），降低了系统整体负载。
- **无状态支撑**：连接的短暂性与独立性是实现无状态上下文的前提条件，确保运行时不持有跨请求的连接态。
- **工具调用前置**：连接建立后，系统方可调用对应能力服务的 JSON Schema 定义的工具接口。

## 应用

- **企业级 Agent 工具调用**：当 Agent 接收到用户请求后，L1 Router 进行意图识别，匹配成功后才建立到具体业务服务（库存、CRM、订单等）的连接，避免所有服务连接常驻。
- **多租户隔离场景**：不同租户的请求各自建立独立的短暂连接，从物理层面确保租户间数据与调用的隔离。
- **可逃逸架构落地**：由于连接是按需且短暂的，替换底层能力服务时不会影响常驻连接，支持组件的热替换与架构的平滑演进。
- **低资源高并发场景**：在并发请求量较大的客服 Agent 等场景下，按需连接策略可以显著降低连接池压力，提升系统吞吐量。
