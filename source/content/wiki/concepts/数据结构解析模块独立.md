# 数据结构解析模块独立

## 定义
该规范要求 Controller 层返回纯 Python 字典或列表，由 Service 层（路由层）统一包装为标准 JSON 格式（包含 `code`、`msg`、`data`、`trace_id` 字段）。请求参数校验通过 Pydantic 模型完成，键名在驼峰与下划线之间自动转换以适配前端和 ORM 的不同需求。该设计还预留了 Protobuf 支持，目前所有路由仅接收和返回 JSON，但架构上已为未来引入 ProtobufOverHTTP 做好准备。

## 关键特征
- **职责隔离**：Controller 仅负责业务逻辑并将结果以 Python 字典或列表返回，不关心响应格式封装。
- **统一响应格式**：路由层负责将 Controller 返回的 Python 对象包装为 `{"code": 0, "msg": "success", "data": {...}, "trace_id": "可选"}` 的标准 JSON 结构。
- **自动命名转换**：Pydantic 验证后得到的驼峰命名字段，通过 `common_sdk` 基类提供的 `convert_dict_to_snake` 方法转换为下划线字段以便 ORM 操作；返回前端时再转回驼峰。
- **协议可扩展性**：当前仅支持 JSON，但架构层面预留了 Protobuf 支持能力，为未来引入 ProtobufOverHTTP 奠定基础。

## 应用
- 后端 API 开发中，Controller 层专注于业务处理，无需手动构造统一响应结构。
- ORM 数据操作场景中，自动将驼峰命名转换为下划线命名以匹配数据库字段。
- 前后端数据交互场景中，前端使用驼峰命名风格，后端 ORM 使用下划线命名风格，两者之间自动适配。
- 未来需要引入 Protobuf 协议的微服务场景中，可平滑迁移而无需重构核心业务代码。
