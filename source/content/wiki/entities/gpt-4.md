## Description
GPT-4 是 [[entities/openai|OpenAI]] 推出的通用大语言模型，在企业级 Agent 架构中常被用作核心推理引擎。在本文所述的架构重构案例中，系统原始设计将所有请求——包括「修改密码」这类高确定性的简单指令——均路由至 GPT-4 进行推理处理，导致 Token 成本是规则引擎的 100 倍。这一案例成为典型的「算力错配」反面教材，说明企业级架构不应将 LLM 视为全能决策者。正确做法是通过 [[concepts/模型路由|模型路由]] 与 [[concepts/意图识别|意图识别]] 进行分层路由，将确定性请求分流到规则引擎或轻量级模型，GPT-4 仅保留给真正需要复杂推理的场景，从而实现有效的 [[concepts/成本管理|成本管理]]。在 VOC 舆情分析系统中，全量数据跑 GPT-4 同样面临成本高且 QPS 跟不上爬虫速度的问题，作者因此采用 [[concepts/分级策略|分级策略]]，仅对复杂长评调用 GPT-4，简单重复评论走缓存或正则处理，进一步印证了精细化管理大模型成本与延迟的工程必要性。此外，业界普遍存在迷信「超级模型」的认知偏差——认为一个 GPT-4 就能解决所有问题，却忽略了 [[concepts/agent-编排|Agent 编排]]（Orchestration）与 [[concepts/确定性工程|确定性工程]]的重要性。即便是顶级模型，也需要在系统级治理框架内运行，未来的架构师核心工作不再是编写函数，而是设计"防呆机制"和"思维链条"，让不可控的模型在可控的框架内运行。
