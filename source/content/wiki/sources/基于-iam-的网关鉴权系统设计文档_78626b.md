# 统一网关鉴权架构设计 - Summary

## 来源
- Original file: [[架构/基于 IAM 的网关鉴权系统设计文档.md]]
- Ingested: 2026-07-28

## 核心内容
本文档详细描述了一套基于 API 网关的统一鉴权系统架构。系统旨在通过[[concepts/统一鉴权|统一鉴权]]机制，将安全校验逻辑从各个业务模块中抽离并集中前置到网关层。核心鉴权流程为：前端携带用户 Token 发起请求，[[entities/网关|网关]]接收并执行[[concepts/token解析|Token解析]]，提取用户标识与 API 路径，随后向[[entities/iam系统|IAM系统]]请求该用户的权限数据。IAM 系统基于[[concepts/rbac权限模型|RBAC权限模型]]和[[concepts/权限计算逻辑|权限计算逻辑]]推导出有效 API 列表。网关获得列表后进行鉴权，若通过则将请求路由至[[entities/业务系统|业务系统]]；若失败则触发[[concepts/403异常处理|403异常处理]]拦截请求。此外，系统引入了[[concepts/权限缓存策略|权限缓存策略]]以减少重复计算，显著提升了整体架构的性能。

## 关键实体
- [[entities/网关|网关]]：API 请求的统一流量入口，负责解析 Token、获取权限并执行鉴权路由。
- [[entities/iam系统|IAM系统]]：核心权限管理组件，负责根据多级关联关系计算并返回用户的有效 API 列表。
- [[entities/业务系统|业务系统]]：请求的实际处理方，专注于核心业务逻辑，无需关心权限校验。

## 关键概念
- [[concepts/统一鉴权|统一鉴权]]：将鉴权逻辑从业务系统中抽离，统一前置到网关层执行的核心架构方法。
- [[concepts/rbac权限模型|RBAC权限模型]]：建立“用户→用户组→角色→权限→菜单→API”多层级联关系的权限管理基础。
- [[concepts/权限计算逻辑|权限计算逻辑]]：IAM 系统推导最终可访问 API 列表的四步核心算法（角色聚合、权限提取、菜单映射、API生成）。
- [[concepts/权限缓存策略|权限缓存策略]]：基于 user_id 的键值对缓存设计，支持 TTL 过期、主动更新与被动淘汰。
- [[concepts/token解析|Token解析]]：网关提取用户身份标识（user_id）的安全验证前置步骤。
- [[concepts/403异常处理|403异常处理]]：网关鉴权失败时直接返回 403 状态码并拦截请求的响应机制。
- [[concepts/用户组角色聚合|用户组角色聚合]]：通过将直接角色与用户组角色取并集，计算用户的有效角色集合。
- [[concepts/权限api缓存|权限API缓存]]：通过缓存机制避免每次请求向 IAM 发起查询，大幅降低系统开销。
- [[concepts/菜单api映射|菜单api映射]]：将抽象的菜单权限转化为具体的后端 API 接口访问控制权限。

## 要点
- **架构解耦**：系统采用网关统一鉴权架构，成功将安全校验逻辑从[[entities/业务系统|业务系统]]中完全剥离至网关层。
- **完整鉴权链路**：标准流程为“前端携带 Token 请求 → 网关解析获取标识 → 向 IAM 获取权限 → 网关执行鉴权 → 转发或直接拒绝”。
- **多级权限模型**：IAM 系统支持“用户→用户组→角色→权限→菜单→API”和“用户→角色→权限→菜单→API”两种维度的关联关系。
- **标准化计算步骤**：权限计算严格遵循“角色聚合 → 权限提取 → 菜单映射 → API生成”四个步骤。
- **高性能缓存设计**：采用基于 user_id 的键值对缓存，同时配备 TTL 过期、主动刷新和被动淘汰三层保障策略。
- **统一异常响应**：鉴权失败时网关直接返回 403 状态码，不将无效请求透传至后端业务系统。
