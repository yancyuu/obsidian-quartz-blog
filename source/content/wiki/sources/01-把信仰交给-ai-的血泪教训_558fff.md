# 把信仰交给 AI 的血泪教训——Agent 落地五个致命大坑 - Summary

## 来源
- 原始文件：[[👩‍💻 个人笔记/公众号/01. 把信仰交给 AI 的血泪教训.md]]
- 收录日期：2026-06-21

## 核心内容

作者「野生想法」在停更两年、专注企业级 Agent 落地实践后，基于 **12 个项目经验**，提炼出四个真实项目中的 **五个致命工程大坑**。文章的核心论断是：**Demo 越聪明，线上越容易崩**——Agent 失败的 99% 是工程问题，而非模型能力问题。

五个致命大坑依次为：**价值观失控触碰信仰红线**、**工具不幂等导致状态混乱**、**多轮对话后失忆**、**知识库污染引发编造事实**、**观测缺失无法定位问题**。针对每个大坑，作者给出了具体的工程化修复方案，并最终汇聚为一套从 Demo 走向生产力的 **六阶段落地框架**。

## 关键实体

- [[entities/信仰咨询agent|信仰咨询Agent]]：第一个致命大坑的真实案例，LLM 的普世价值观与特定信仰教义发生冲突，揭示了 Agent 价值观失控的风险。
- [[entities/订餐agent|订餐Agent]]：第二个致命大坑的核心案例，暴露了工具调用不幂等和状态不一致问题。
- [[entities/客服agent|客服Agent]]：多轮对话失忆问题的典型案例，因缺乏显式流程控制导致上下文混乱。
- [[entities/企业问答agent|企业问答Agent]]：知识库污染问题的案例，Agent 引用过期文档并"自信地胡说"。

## 关键概念

- [[concepts/双层白名单|双层白名单]]：解决价值观失控的核心防护机制，将风险管理前置到 LLM 决策之前。
- [[concepts/不答策略|不答策略]]：配合白名单使用的"拒答/澄清/转人工"三段式兜底策略。
- [[concepts/幂等键|幂等键]]：保障工具调用事务安全的基础机制，防止重复创建资源。
- [[concepts/订单原子化|订单原子化]]：将价格计算与库存校验前置为原子服务，输出数据快照确保一致性。
- [[concepts/补偿链|补偿链]]：工具调用失败时执行回滚和资源释放的安全保障机制。
- [[concepts/显式节点图|显式节点图]]：解决多轮对话失忆的核心方法，将复杂流程结构化。
- [[concepts/阶段机|阶段机]]：限制每个节点可用工具和流程走向的有限状态机。
- [[concepts/上下文窗口压力|上下文窗口压力]]：Agent 多轮对话失忆的深层原因。
- [[concepts/数据分层隔离|数据分层隔离]]：将文档分为生产库/沙盒库/过期库，确保知识权威性。
- [[concepts/反思型rag|反思型RAG]]：引入自我校对机制，让 Agent 在回答前验证引用证据的准确性。
- [[concepts/验证链cove|验证链CoVe]]：反思型 RAG 的具体实现形式，强制二次核对关键句。
- [[concepts/结构化检索|结构化检索]]：采用结构化索引与混合召回提高证据检索精准度。
- [[concepts/agent观测体系|Agent观测体系]]：通过四类埋点将黑盒变为白盒，实现全链路追踪。
- [[concepts/4+1核心指标|4+1核心指标]]：成功率、P95延时、CPT成本、误导率、用户步骤的量化评估标准。
- [[concepts/sla定义|SLA定义]]：落地框架第一阶段，明确成功率阈值与降级策略。
- [[concepts/灰度与回滚|灰度与回滚]]：落地框架最终阶段，保证上线稳定性。
- [[concepts/对抗样例|对抗样例]]：上线前针对关键意图配备的包含方言、口误等干扰的测试用例。
- [[concepts/工具重放|工具重放]]：所有工具调用必须支持的可重放机制，用于精确回溯问题。

## 要点

- **Demo 越聪明，线上越容易崩**：Agent 失败的 99% 是工程问题而非模型问题，核心论断贯穿全文。
- **价值观失控是最严重的崩坏**：必须通过代码（非 Prompt）将边界写死，建立 [[concepts/双层白名单|双层白名单]] 和 [[concepts/不答策略|三段式兜底]]。
- **交易场景必须保障事务安全**：[[concepts/幂等键|幂等键]]、[[concepts/订单原子化|订单原子化]] 和 [[concepts/补偿链|补偿链]] 构成完整的事务安全保障；Agent 的核心价值是**构建**订单而非**支付**订单。
- **复杂流程不能依赖隐式记忆**：[[concepts/上下文窗口压力|上下文窗口压力]] 会导致"人格分裂"，必须用 [[concepts/显式节点图|显式节点图]] 和 [[concepts/阶段机|阶段机]] 分而治之。
- **知识管理需要系统化防护**：[[concepts/数据分层隔离|数据分层隔离]] + [[concepts/结构化检索|结构化检索]] + [[concepts/反思型rag|反思型RAG]] 三管齐下，防止编造事实。
- **可观测性是优化的前提**：只看结果（黑盒）无法定位问题，必须追踪意图、检索、工具的完整执行过程（白盒）。
- **六阶段落地框架**：[[concepts/sla定义|SLA定义]] → 意图权限 → 工具事务 → 知识版本 → 观测评测 → [[concepts/灰度与回滚|灰度回滚]]，构成从 Demo 到生产力的完整方法论。
- **上线前低成本正确性自检**：[[concepts/对抗样例|对抗样例]]、[[concepts/工具重放|工具重放]]、事故演练、看板极简化、兜底明确，缺一不可。
