# 异步是如何实现的 - 摘要

## 来源
- 原始文件: [[💻基础知识/计算机原理/异步如何实现的.md]]
- 录入时间: 2026-07-28

## 核心内容
本文深入剖析了 [[entities/asyncio|asyncio]] 背后的底层实现原理，而非仅仅介绍用法。文章围绕三大核心机制展开：[[concepts/事件循环|事件循环]]、[[concepts/io多路复用|IO多路复用]]和[[concepts/协程|协程]]。首先指出异步 IO 的本质是**单线程 + 事件循环 + IO 多路复用**，通过协程的暂停与恢复实现高并发。文章详细阐述了事件循环的[[concepts/非抢占式调度|非抢占式调度]]工作流程，并利用 [[entities/epoll|epoll]] 等系统调用等待 IO 就绪。此外，文章讨论了 asyncio 与 [[concepts/gil|GIL]] 的关系，解释了为何[[concepts/协程|协程]]中不能运行 CPU 密集型任务——因为[[concepts/io阻塞|IO阻塞]]或计算会阻塞整个事件循环，并提供了使用 [[concepts/进程调度|进程调度]]（`run_in_executor`）将任务委托给线程池或进程池的解决方案。文章基于 [[entities/python|Python]] 3.7+ 的现代 API 进行讲解。

## 关键实体
- [[entities/asyncio|asyncio]] - Python 标准库中用于编写并发代码的核心模块
- [[entities/epoll|epoll]] - Linux 内核中的可扩展 IO 多路复用机制
- [[entities/python|Python]] - 本文讨论异步编程所基于的高级编程语言

## 关键概念
- [[concepts/事件循环|事件循环]] - 异步编程的调度核心，负责循环执行就绪队列中的任务
- [[concepts/协程|协程]] - 用户态的、可暂停恢复的轻量级函数
- [[concepts/io多路复用|IO多路复用]] - 允许单个线程同时监控多个文件描述符的网络IO模型
- [[concepts/gil|GIL]] - CPython 的全局解释器锁机制
- [[concepts/异步io|异步IO]] - 发起 IO 操作后不等待完成，转去执行其他任务的IO处理模型
- [[concepts/非抢占式调度|非抢占式调度]] - 任务必须完整执行完或主动交出控制权的调度方式
- [[concepts/io阻塞|IO阻塞]] - 执行 IO 操作时当前线程被挂起等待的现象
- [[concepts/异步并发检索|异步并发检索]] - 利用协程在单线程内同时发起多个检索请求
- [[concepts/进程调度|进程调度]] - 通过多进程机制将 CPU 密集型任务剥离出事件循环

## 要点
- **异步本质**：异步 IO 的并发并非多线程，而是**单线程 + 事件循环 + IO 多路复用**的结合。
- **协程机制**：协程是用户态可暂停恢复的函数，底层基于生成器（yield）的状态机实现。
- **调度核心**：事件循环通过非抢占式调度，在协程 `await` 暂停时利用 epoll 等机制监听 IO 就绪状态。
- **规避 GIL**：asyncio 单线程运行规避了 GIL 竞争，但无法处理 CPU 密集型任务，否则会阻塞事件循环。
- **解决方案**：CPU 密集型任务应通过 `loop.run_in_executor()` 或多进程剥离出主线程。
- **现代 API**：推荐使用 `asyncio.run()` 替代已过时的 `get_event_loop()` 写法。
