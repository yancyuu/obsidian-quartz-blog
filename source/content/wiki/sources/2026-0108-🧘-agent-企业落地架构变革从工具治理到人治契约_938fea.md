## 核心内容
本文基于阿里云关于 AI 应用架构的深度文章，结合作者在构建可演化智能体系统中的实践经验，系统阐述了 AI Agent 从实验室走向企业生产环境过程中的架构演进与治理策略。文章的核心理论洞察是 [[concepts/人治|人治]] ——企业引进 [[entities/mcp|MCP]] 协议的价值不仅在于技术解耦，更在于通过"契约"强制划分业务和组织边界。文章将企业落地路径分为 [[concepts/全新开发|全新开发]] 和 [[concepts/存量改造|存量改造]] 两条路线，并提出了 [[concepts/双模执行架构|双模执行架构]] 来应对新旧系统并存的挑战。在架构新范式方面，详细介绍了 [[concepts/ai网关|AI网关]]、[[entities/nacos|Nacos]] 与 [[concepts/mcp-registry|MCP Registry]] 的工具资源管理，以及 [[concepts/agent编排框架|Agent编排框架]]、[[concepts/agent运行时|Agent运行时]]、[[concepts/agent观测平台|Agent观测平台]] 三角职责划分和 [[entities/fc|FC]] 与 [[entities/k8s|K8s]] 的计算环境选型。

## 关键实体
- [[entities/mcp|MCP]]：企业 Agent 架构中的通用"契约"，强制划分业务和组织边界
- [[entities/agentbay|Agentbay]]：容器化的 RPA 执行通道，用于对老旧黑盒系统进行非侵入式操作
- [[entities/nacos|Nacos]]：兼具微服务与 MCP 服务注册能力的服务发现核心组件
- [[entities/higress|Higress]]：AI 网关实现方案之一，负责统一管控模型调用
- [[entities/deepseek|DeepSeek]]：国产大模型服务提供方
- [[entities/fc|FC]]：阿里云函数计算服务，适配事件驱动的 Agent 计算环境
- [[entities/k8s|K8s]]：适用于强合规和高负载场景的容器化计算环境

## 关键概念
- [[concepts/人治|人治]]：架构的解耦能力本质上是组织治理能力的体现
- [[concepts/双模执行架构|双模执行架构]]：通过 API（快）与 RPA（慢）双通道解决存量改造问题
- [[concepts/ai网关|AI网关]]：所有 Agent 访问模型服务的唯一出口
- [[concepts/agent运行时|Agent运行时]]：Agent 组件铁三角中"下沉的核心"
- [[concepts/存量改造|存量改造]]：绝大多数企业落地 Agent 的主战场
- [[concepts/一体式工具架构|一体式工具架构]]：探索期可行但企业级需要向解耦演进
- [[concepts/模型路由|模型路由]]：底层模型间的自动切换与容灾策略
- [[concepts/mcp-registry|MCP Registry]]：通过元数据映射实现现存业务零改造接入
- [[concepts/成本管理|成本管理]]：AI 网关中管理者角色的核心职责

## 要点
- 企业引进 MCP 协议的核心价值不仅在于技术解耦，更在于通过"契约"强制划分业务和组织边界，实现从工具治理到人治的转变
- 企业落地 Agent 有两条路径：全新开发（Greenfield）和存量改造（Legacy Modernization），后者是绝大多数企业的主战场
- 存量改造的"双模执行架构"通过 API 通道（快模式）和 RPA 通道（Agentbay+LVM 慢模式）解决新旧系统并存问题
- AI 应用架构新范式包含四大核心：AI 网关收敛模型能力、Nacos + MCP Registry 管理工具资源、Agent 组件铁三角、FC/K8s 计算环境选型
- Agent 组件铁三角：编排框架（Brain）管理 Prompt 和记忆、运行时（Runtime）执行快慢双模、观测平台（Observability）监控全链路
- FC 适合事件驱动和快速验证场景，K8s 适合强合规、稳定高负载和深度自定义场景
- AI 开发人员需具备异步编程能力、上下文优化能力，以及无过强路径依赖的软能力
