# 后端项目代码规范 - 摘要

## 来源
- 原始文件: [[架构/应用开发规范/应用开发规范.md]]
- 录入日期: 2026-07-28

## 核心内容
本文档是一份基于 [[entities/python|Python]] 3.11+ 的后端项目代码规范指南，技术栈涵盖 [[entities/sanic|Sanic]]、[[entities/langgraph|LangGraph]] 和 [[entities/langchain|LangChain]]。规范核心在于严格的[[concepts/模块职责划分规范|分层架构]]：服务层仅处理路由接入，控制器层专注业务逻辑，模型层定义数据结构。架构设计遵循[[concepts/接口不动协议可插拔|协议可插拔]]原则，确保控制器只处理纯 Python 数据结构，与传输协议完全解耦。接口统一采用 [[concepts/rpc风格路由|RPC 风格路由]]设计，数据校验全面依赖 [[entities/pydantic|Pydantic]]。项目将 [[entities/common_sdk|common_sdk]] 与 [[entities/ai_sdk|ai_sdk]] 作为独立模块分离，由 [[entities/poetry|Poetry]] 进行分模块[[concepts/依赖管理规范|依赖管理]]，并配合多阶段 [[concepts/dockerfile配置规范|Docker 构建]]实现容器化部署。配置方面采用 [[concepts/配置驱动|配置驱动]]方法，敏感信息存于环境变量，后续计划对接 [[entities/nacos|Nacos]]。此外，规范还明确了[[concepts/统一异常捕获|全局异常处理]]中间件、标准化 JSON 响应格式以及基于 [[entities/pytest|pytest]] 的[[concepts/测试规范|异步测试]]体系。

## 要点
- **严格的目录分层**：明确划分 services（路由）、controller（业务）、models（ORM）、scheme（数据校验）职责边界，分离出独立的 common_sdk 和 ai_sdk。
- **协议解耦设计**：Controller 层仅处理纯 Python 数据结构（输入与输出），不依赖具体的传输协议，为未来引入 Protobuf 或 gRPC 预留扩展能力。
- **标准化接口交互**：全面采用 RPC 风格的 HTTP+JSON 路由设计，使用 Pydantic 统一校验入参，并支持驼峰与下划线的自动转换以适配前端与 ORM。
- **完善的防护与追踪**：通过全局异常中间件统一捕获错误，对外输出标准化 JSON 响应格式（包含 code、msg、data、trace_id）。
- **规范的工程化流程**：依赖管理使用 Poetry，配合多阶段 Docker 构建生成轻量级镜像；敏感配置通过 pydantic_setting 驱动，禁止在 SDK 层硬编码实例。
