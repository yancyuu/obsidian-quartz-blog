# 可逃逸架构设计模式（Excalidraw 架构图）- 摘要

## 来源
- 原始文件: [[../../架构/应用开发规范/excalid/渐进式披露架构]]
- 录入日期: 2026-07-28

## 核心内容
本架构图描绘了一种被称为「可逃逸架构」（The Escape Hatch）的 Agent 系统设计模式。其核心思想是通过协议层实现能力与执行解耦，使 [[concepts/无状态上下文|无状态上下文]]成为可能。整体架构分为三层：底层 [[entities/capability-layer|能力层]] 包含 [[entities/inventory-service|库存服务]]、[[entities/crm-service|CRM服务]] 和 [[entities/rpa-worker|RPA Worker]] 等业务服务；中间 [[concepts/protocol-layer|协议层]] 以 [[entities/mcp|MCP]] / OpenAPI 为标准接口；顶层 [[entities/agent-runtime|Agent Runtime]] 负责 [[concepts/意图识别intentclassifier|意图识别]]与[[concepts/任务执行task-executor|任务执行]]。

该架构的关键创新在于引入了[[concepts/技能注册表skill-registry仅包含技能名|仅包含技能名的注册表]]机制。系统通过[[concepts/按需加载|按需加载]]策略，在识别到用户意图后才动态加载所需工具定义，有效避免了[[concepts/上下文污染|上下文污染]]问题。完整工作流涵盖五个步骤：[[concepts/user-request|用户请求]]输入 → 意图匹配 → 激活特定技能 → [[concepts/on-demand-connection|动态建立连接]] → 调用 [[concepts/json-schema|JSON Schema]] 工具接口。

## 关键实体
- [[entities/mcp|MCP]] - 协议层核心标准，作为能力层与运行时之间的"逃生舱"
- [[entities/rpa-worker|RPA Worker]] - 能力层中的流程自动化执行单元
- [[entities/agent-runtime|Agent Runtime]] - 智能体运行时核心，管理任务调度与生命周期
- [[entities/capability-layer|Capability Layer]] - 由多个 MCP Servers 组成的底层基础设施
- [[entities/inventory-service|Inventory Service]] - 库存查询业务服务实例
- [[entities/crm-service|CRM Service]] - 客户关系管理服务实例
- [[entities/management|Management]] - 技能管理模块，维护轻量级注册表

## 关键概念
- [[concepts/可逃逸架构|可逃逸架构]] - 通过协议层实现能力与执行解耦的系统设计模式
- [[concepts/l1-router|L1 Router]] - 负责意图识别与请求分类的第一层路由组件
- [[concepts/l2-worker|L2 Worker]] - 负责具体任务执行的第二层工作组件
- [[concepts/skill-registry|Skill Registry]] - 仅存储技能名称的轻量级索引目录
- [[concepts/无状态上下文|无状态上下文]] - 运行时不持有持久工具定义的核心理念
- [[concepts/按需加载|按需加载]] - 运行时根据意图动态加载工具的调用策略
- [[concepts/上下文污染|上下文污染]] - 本架构致力于解决的核心问题
- [[concepts/protocol-layer|Protocol Layer]] - 实现解耦的关键标准化中间层
- [[concepts/pure-intent|Pure Intent]] - 保证意图纯净性、不受干扰的设计原则

## 要点
- **三层解耦设计**：[[concepts/可逃逸架构|可逃逸架构]]通过能力层、协议层、运行时层的分层实现了 Agent 能力与执行的彻底解耦。
- **MCP 作为逃生舱**：[[entities/mcp|MCP]] / OpenAPI 标准作为协议层接口，实现了「接口不动协议可插拔」的设计目标。
- **两级路由架构**：[[entities/agent-runtime|Agent Runtime]] 采用 [[concepts/l1-router|L1 Router]]（意图识别）+ [[concepts/l2-worker|L2 Worker]]（任务执行）的分层处理模式。
- **注册表轻量化**：[[concepts/skill-registry|Skill Registry]] 仅包含技能名而不含工具定义，是从源头消除 [[concepts/上下文污染|上下文污染]] 的关键机制。
- **运行时按需加载**：工具定义通过 [[concepts/按需加载|按需加载]] 策略在运行时动态拉取，保持 [[concepts/无状态上下文|无状态上下文]] 的纯净性。
- **五步完整工作流**：从输入指令到调用工具的完整链路为——输入指令 → 匹配意图 → 激活技能 → 动态建立连接 → 调用工具 JSON Schema。
