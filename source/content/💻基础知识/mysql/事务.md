# 事务

> 事务是数据库操作的逻辑单元，**ACID** 是灵魂。本文讲清 ACID 的实现原理 + 四隔离级别与三大并发问题的对应关系——这是 MySQL 必考题。

## 一、什么是事务

事务（Transaction）是一组操作，要么全部成功提交，要么全部回滚，是一个**不可分割的工作单元**。

```sql
BEGIN;          -- 或 START TRANSACTION
UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;
COMMIT;         -- 或 ROLLBACK
```

## 二、ACID 及其实现原理（高频）

| 特性         | 含义                     | InnoDB 如何实现                            |
| ------------ | ------------------------ | ------------------------------------------ |
| **A 原子性** | 全做或全不做，失败回滚   | **undo log**（回滚日志）                   |
| **C 一致性** | 执行前后数据保持一致状态 | 由 A/I/D 共同保证（一致性是目标）          |
| **I 隔离性** | 并发事务互不干扰         | **锁 + [MVCC](MVCC（多版本并发控制）.md)** |
| **D 持久性** | 提交后永久保存，宕机不丢 | **redo log**（重做日志）+ Buffer Pool      |

> 关键：ACID 不是凭空实现，而是靠 **undo log（A）+ redo log（D）+ 锁/MVCC（I）** 三个机制落地，最终保证一致性（C）。详见 [mysql日志](mysql日志.md)。

## 三、并发事务的三大问题

| 问题           | 含义                                                              |
| -------------- | ----------------------------------------------------------------- |
| **脏读**       | 读到别的事务**未提交**的修改                                      |
| **不可重复读** | 同一事务内两次读同一行，结果不同（别的事务 **update** 并提交了）  |
| **幻读**       | 同一事务内两次范围查询，行数不同（别的事务 **insert/delete** 了） |

> 不可重复读侧重「同一行被改」，幻读侧重「行数变化（新增/删除）」。

---

## 四、四个隔离级别

隔离级别越高，一致性越强，并发越低：

| 隔离级别                | 脏读    | 不可重复读 | 幻读        |
| ----------------------- | ------- | ---------- | ----------- |
| **读未提交** RU         | ❌ 可能 | ❌ 可能    | ❌ 可能     |
| **读已提交** RC         | ✅ 避免 | ❌ 可能    | ❌ 可能     |
| **可重复读** RR ⭐      | ✅ 避免 | ✅ 避免    | ✅ 基本避免 |
| **串行化** Serializable | ✅ 避免 | ✅ 避免    | ✅ 避免     |

```mermaid
flowchart LR
    RU[读未提交] -->|解决脏读| RC[读已提交]
    RC -->|解决不可重复读| RR[可重复读]
    RR -->|解决幻读| S[串行化]
    style RR fill:#dcfce7
```

> - **MySQL InnoDB 默认 RR**（多数其他数据库默认 RC）
> - InnoDB 的 RR 通过 **[MVCC](MVCC（多版本并发控制）.md)**（快照读）+ **间隙锁**（当前读）**基本解决幻读**
> - 实际生产大多用 RC（如阿里/美团默认 RC），需根据业务权衡

## 五、事务语法要点

| 语句                                  | 作用                   |
| ------------------------------------- | ---------------------- |
| `BEGIN` / `START TRANSACTION`         | 开启事务               |
| `COMMIT`                              | 提交                   |
| `ROLLBACK`                            | 回滚                   |
| `SAVEPOINT name`                      | 设置保存点，可部分回滚 |
| `SET TRANSACTION ISOLATION LEVEL ...` | 设置隔离级别           |

> **隐式提交**：执行 DDL（CREATE/ALTER/DROP）时会**自动提交**当前事务，这是常见坑点。
> **自动提交**：默认 `autocommit=1`，每条语句单独一个事务。

## 六、面试速答

> **Q：事务的 ACID 怎么实现的？**
> A：A 靠 undo log（回滚）、D 靠 redo log（重做）、I 靠锁 + MVCC，三者共同保证 C（一致性）。C 是目标，AID 是手段。

> **Q：MySQL 的隔离级别？默认哪个？**
> A：四个级别 RU/RC/RR/Serializable。InnoDB 默认 **RR**，通过 MVCC + 间隙锁基本解决幻读。很多互联网公司改用 RC。

> **Q：脏读、不可重复读、幻读区别？**
> A：脏读读未提交；不可重复读是同事务两次读同行结果不同（被 update）；幻读是范围查询行数变化（被 insert/delete）。

> **Q：RR 怎么解决幻读的？**
> A：快照读靠 MVCC（复用 ReadView）；当前读靠间隙锁/临键锁阻止别的事务插入。详见 [MVCC](MVCC（多版本并发控制）.md)。
