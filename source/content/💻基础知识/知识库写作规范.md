# 💻 基础知识库 · 写作规范

> 本文件是整个 `💻基础知识` 知识库的**唯一规范来源**。所有新增、修改、整理都以此为准。它本身就是知识库的一部分，遇到分歧以这里为准。

---

## 一、知识库定位

这是面向 **后端/全栈工程师面试 + 日常开发查阅** 的个人技术知识库。每篇笔记要同时满足两个目标：

1. **查得到**：结构清晰，能快速定位某个知识点。
2. **答得出**：按"面试怎么问 → 怎么答 → 为什么 → 踩坑"组织，能直接用于面试复述。

不追求大而全的搬运，追求**自己能讲明白**。

---

## 三、标签体系（三层，强制）

所有文件**必须**包含前两层，第三层按需。

```yaml
tags:
  - basic-knowledge # ① 总属标签：标记属于本知识库（必有）
  - kb/network # ② 领域标签：nested 形式，对应学科分类（必有）
  - kb/network/tcp # ③ 子主题标签：nested 形式，更细的主题（按需）
  - tcp # ④ 关键词标签：扁平 kebab-case，便于检索/面试归类（按需）
```

### 标签书写规则

1. 一律 **小写 kebab-case**：`high-concurrency`，不是 `HighConcurrency`。
2. nested 标签用 `/`：`kb/database/mysql/innodb`，Quartz 会自动生成标签树。
3. **不放错标签**：标签必须和内容强相关。例如
   - ❌ `计算机网络.md` 标 `oauth2`（OAuth2 只是文末举例，不是主题）
   - ❌ `进程线程协程.md` 标 `kafka`（与 Kafka 无关）
   - ❌ `注册树模式.md` 标 `data-structure`（设计模式不是数据结构）
4. 一个文件**领域标签只选一个主领域**，避免跨域混乱。

## 五、文件命名规范

1. **中文命名**，语义清晰，能一眼看出主题。
2. **禁止**：空格、emoji、Notion 导出的 hash 后缀（如 `d422e19e...`）。
3. 多概念对比用「与」「对比」：`GET与POST的区别.md`、`HTTP与HTTPS.md`。
4. 复合词用连字符：`TCP-IP协议.md`、`select-poll-epoll.md`。
5. 同主题系列用统一前缀：`MySQL性能优化-索引.md`。

## 六、引用规范

### 6.1 笔记间链接（建立知识网络）

遵循本仓库 Obsidian 配置（`useMarkdownLinks: true` + `newLinkFormat: relative`），**统一用相对路径 Markdown 链接**、带 `.md` 后缀，**不用 `[[wikilink]]`**：

```markdown
（本规范位于根目录，以下路径均相对根目录解析）

- 指向子目录：详见 [pdb调试](计算机原理/pdb调试.md)
- 指向另一子目录：[事务](mysql/事务.md)
- 同目录文件互相引用时无需加目录前缀（相对路径以「当前文件所在目录」为基准）
```

- 相对路径以**当前文件所在目录**为基准，跨目录用 `../`。
- 改文件名/移目录后，**必须同步更新引用**（Obsidian 已开启 `alwaysUpdateLinks: true` 自动更新）。
- 每篇笔记开头或末尾放一个 `## 相关笔记` 区块，列 2-4 个强相关链接。

### 6.2 图片

- 本地图片统一放 `💻基础知识/images/`，引用用**相对路径**（子目录笔记用 `../images/文件名`，文件名含空格用 `%20` 编码，如 `../images/Untitled%2014.png`）。
- **新增图优先用 Mermaid**（见第七节），不依赖外部资源、永不失效、可交互。
- `images/` 下已有图（Untitled / image 系列）虽命名非语义化，但**引用映射已建立且稳定，不强行重命名**（命名丢失归属、重命名易断链）；确需语义化应在 Obsidian 内重命名并依赖 `alwaysUpdateLinks` 同步。
- 禁止直接外链可能失效的图床（zhimg、临时 cdn）；确需外链图，注明来源并优先用官方文档图。

### 6.3 外部权威链接

每个核心知识点末尾加 `## 参考` 区块，引用**官方文档 / 经典书籍 / 权威博客**，提升可信度与可深挖性：

```markdown
## 参考

- [MySQL 官方文档 · InnoDB Multi-Versioning](https://dev.mysql.com/doc/refman/8.0/en/innodb-multi-versioning.html)
- 《高性能 MySQL》第 3 版，第 1 章
```

## 八、内容质量标准（每篇笔记的理想结构）

一篇完整的知识点笔记应包含：

1. **一句话定义** + 一句话价值（为什么重要）。
2. **原理/机制**（配图）。
3. **怎么用 / 怎么实现**（代码示例）。
4. **面试怎么问 → 怎么答**（高频问题 + 标准回答要点）。
5. **踩坑 / 最佳实践**。
6. **相关笔记**（双链）。
7. **参考**（权威外链）。

> 老笔记不强制全部补齐，但新写/重写时按此结构；整理时优先补 4、6、7。

## 九、维护守则

- 改文件名/移目录后，**立即同步更新所有相对路径引用和索引链接**（Obsidian 已开启 `alwaysUpdateLinks` 自动更新）。
- 发现重复内容，**合并到更完整的专题页**，旧文件转成跳转或删除。
- 索引页（`基础知识索引.md`）必须与实际文件 **100% 对齐**，新增/删除文件同步更新索引。
