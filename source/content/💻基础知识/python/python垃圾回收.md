Python 的垃圾回收（Garbage Collection，GC）负责自动管理内存分配和回收：对象不再被使用时释放内存，避免长期运行程序不断泄漏。

Python 的 GC 不是单一机制，而是：

1. **引用计数为主**
2. **标记-清除解决循环引用**
3. **分代回收提升扫描效率**

## 1. 引用计数

每个对象都有一个引用计数，表示当前有多少引用指向它。

- 新增引用：计数 +1
- 引用离开作用域或被删除：计数 -1
- 引用计数变成 0：对象立即释放

优点：

- 实现简单
- 实时性好，对象没有引用后通常能马上释放
- 回收成本分摊到程序运行过程中

缺点：

- 维护引用计数有额外开销
- 无法处理循环引用

## 2. 循环引用

循环引用是指两个或多个对象互相引用，导致它们的引用计数永远不为 0。

```python
class A:
    def __init__(self):
        self.obj = None

a = A()
b = A()
a.obj = b
b.obj = a
```

如果 `a` 和 `b` 不再被外部使用，单靠引用计数仍然无法释放它们，因为两者互相持有引用。

## 3. 标记-清除

为了解决循环引用，Python 会从可达对象出发做标记：

1. 标记仍然可以访问到的对象
2. 没有被标记的对象就是不可达对象
3. 清理不可达对象占用的内存

这部分主要由 `gc` 模块管理。

## 4. 分代回收

Python 把对象分成三代：

- **第 0 代**：新创建对象，生命周期通常较短
- **第 1 代**：从第 0 代中存活下来的对象
- **第 2 代**：存活更久的对象

新对象会先进入第 0 代。第 0 代回收频率最高，第 1 代和第 2 代回收频率较低。

这样做的依据是：大多数对象生命周期很短，优先检查新对象更划算。

## 5. 触发垃圾回收

常见触发方式：

1. 手动调用 `gc.collect()`
2. `gc` 模块内部计数器达到阈值
3. 程序退出时清理

常用调试方法：

```python
import gc

gc.enable()       # 启用垃圾回收
gc.disable()      # 禁用垃圾回收
gc.collect()      # 手动触发
gc.get_count()    # 查看各代计数
gc.get_stats()    # 查看统计信息
```

## 6. `__del__` 与清理风险

如果对象定义了 `__del__`，循环引用的清理会更复杂。

尤其是继承场景中，如果重写了 `__del__` 但没有调用父类清理逻辑，可能导致资源没有被正确释放。

因此不建议把关键资源释放完全依赖 `__del__`，更推荐：

- 使用上下文管理器 `with`
- 显式调用 `close()` / `release()`
- 使用 `try/finally` 保证清理

## 7. 弱引用

弱引用不会增加对象的引用计数，因此不会阻止对象被垃圾回收。

典型场景是缓存：希望能复用对象，但又不希望缓存本身阻止对象释放。

```python
import weakref

class A:
    pass

obj = A()
ref = weakref.ref(obj)
print(ref())

del obj
print(ref())  # None
```

## 总结

Python GC 的核心逻辑是：

- 引用计数负责大多数对象的即时释放
- 标记-清除解决循环引用
- 分代回收减少全量扫描成本
- `gc` 模块提供手动触发和调试能力
- 复杂对象清理不要过度依赖 `__del__`
