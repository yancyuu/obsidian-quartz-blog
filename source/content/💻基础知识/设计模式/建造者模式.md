# 建造者模式

> 建造者模式把复杂对象的构造过程拆成连续步骤，使同一构造过程可以生成不同表示，并避免一个包含大量可选参数的构造函数。

## Python 示例

```python
from dataclasses import dataclass, field

@dataclass(frozen=True)
class HttpRequest:
    method: str
    url: str
    headers: dict[str, str]
    body: bytes | None

class HttpRequestBuilder:
    def __init__(self, url: str):
        self._method = "GET"
        self._url = url
        self._headers: dict[str, str] = {}
        self._body: bytes | None = None

    def method(self, value: str):
        self._method = value
        return self

    def header(self, key: str, value: str):
        self._headers[key] = value
        return self

    def body(self, value: bytes):
        self._body = value
        return self

    def build(self) -> HttpRequest:
        if self._method == "GET" and self._body is not None:
            raise ValueError("GET request cannot contain body")
        return HttpRequest(
            method=self._method,
            url=self._url,
            headers=dict(self._headers),
            body=self._body,
        )
```

```python
request = (
    HttpRequestBuilder("https://api.example.com/orders")
    .method("POST")
    .header("Content-Type", "application/json")
    .body(b"{}")
    .build()
)
```

## 什么时候使用

- 构造步骤较多，并且有顺序或校验要求；
- 同一构造流程需要产生不同配置；
- 希望最终对象不可变；
- 直接构造会出现大量布尔参数或长参数列表。

## Builder 与 Factory

| 模式 | 关注点 |
|---|---|
| 工厂 | 决定创建哪一种对象 |
| 建造者 | 决定一个复杂对象如何分步骤构造 |

Python 的关键字参数、`dataclass` 和配置对象已经能解决很多简单构造问题，不必机械地增加 Builder。

> [!tip] 面试回答
> Builder 适合构造复杂对象，把步骤、校验和最终生成分开；Director 是可选角色。对象简单时，关键字参数或 dataclass 更直接。
