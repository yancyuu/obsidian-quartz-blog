# Python 动态创建类与元编程

> 动态创建类是 Python 的元编程技术，不属于 GoF 设计模式。它用于在运行时生成类型、自动注册子类或统一修改类定义，常见于 ORM、序列化框架和插件系统。

## 类也是对象

普通类定义：

```python
class User:
    role = "member"
```

等价的动态形式：

```python
User = type("User", (object,), {"role": "member"})
user = User()
print(user.role)
```

`type(name, bases, namespace)` 的三个参数分别是类名、父类元组和类命名空间。

## 更实际的用法：自动注册插件

```python
class Plugin:
    registry: dict[str, type["Plugin"]] = {}

    def __init_subclass__(cls, *, name: str, **kwargs):
        super().__init_subclass__(**kwargs)
        if name in cls.registry:
            raise ValueError(f"duplicate plugin: {name}")
        cls.registry[name] = cls

class EmailPlugin(Plugin, name="email"):
    def run(self):
        return "send email"

plugin = Plugin.registry["email"]()
```

相比直接使用元类，`__init_subclass__` 和类装饰器通常更容易理解。

## 元类

```python
class ModelMeta(type):
    def __new__(mcls, name, bases, namespace):
        namespace["table_name"] = name.lower()
        return super().__new__(mcls, name, bases, namespace)

class Model(metaclass=ModelMeta):
    pass

class Order(Model):
    pass

assert Order.table_name == "order"
```

元类负责创建“类对象”，适合必须统一控制类定义过程的框架级能力。

## 技术选择

| 需求 | 优先选择 |
|---|---|
| 只生成一个简单类 | `type()` |
| 子类定义时自动注册 | `__init_subclass__` |
| 给类增加少量行为 | 类装饰器 |
| 控制类创建规则、收集字段 | 元类 |
| 只需要创建不同实例 | 工厂模式，不需要动态类 |

## 常见误区

- ORM 通常使用描述器、类装饰器、`__init_subclass__` 或元类组合，不是简单把字段类型放进类字典；
- 动态类不等于动态代理；代理强调控制对真实对象的访问；
- 元类会提高阅读、类型检查和调试成本，应优先使用更简单机制；
- 不要把来自不可信输入的字符串直接执行为代码。

> [!tip] 面试回答
> Python 中类是由元类创建的对象，`type()` 既能查询类型，也能动态创建类。工程中优先考虑类装饰器和 `__init_subclass__`，只有需要控制类创建过程时才使用自定义元类。
