# 模板方法模式

> 模板方法在父类中固定算法或业务流程骨架，把可变化步骤留给子类实现。它通过继承复用流程，而策略模式通过组合替换行为。

## Python 示例：数据导入流程

```python
from abc import ABC, abstractmethod

class Importer(ABC):
    def run(self, source: str) -> int:
        raw = self.read(source)
        rows = self.parse(raw)
        valid_rows = [row for row in rows if self.validate(row)]
        self.save(valid_rows)
        return len(valid_rows)

    @abstractmethod
    def read(self, source: str) -> str: ...

    @abstractmethod
    def parse(self, raw: str) -> list[dict]: ...

    def validate(self, row: dict) -> bool:
        return bool(row)

    @abstractmethod
    def save(self, rows: list[dict]) -> None: ...
```

`run()` 是不可随意改变的流程骨架，子类只实现读取、解析和保存步骤。

## 适用场景

- 多个流程步骤和顺序基本一致；
- 框架需要定义生命周期和扩展钩子；
- 希望避免多个子类复制同一流程。

## 与策略模式的区别

| 模板方法 | 策略 |
|---|---|
| 基于继承 | 基于组合 |
| 父类控制完整流程 | Context 委托给可替换算法 |
| 编译/定义时确定扩展点 | 运行时更容易切换 |

## 常见误区

- 父类暴露太多 Hook 会形成“脆弱基类”；
- 子类不应破坏流程契约；
- 如果变化维度很多，优先使用策略或 Pipeline 组合，而不是深继承。

> [!tip] 面试回答
> 模板方法固定流程骨架，子类实现变化步骤，适合框架生命周期。它复用方便但耦合继承；变化频繁或需要运行时组合时，策略通常更灵活。
