# 注册表模式（Registry）

> Registry 用一个键到对象、类型或工厂的映射，集中完成注册和查找。“注册树”是部分 PHP 资料中的叫法，但它不要求是树结构，也不属于 GoF 23 种模式。

## 基本结构

```python
from collections.abc import Callable
from typing import Any

class Registry:
    def __init__(self):
        self._factories: dict[str, Callable[[], Any]] = {}

    def register(self, name: str, factory: Callable[[], Any]) -> None:
        if name in self._factories:
            raise ValueError(f"duplicate registration: {name}")
        self._factories[name] = factory

    def create(self, name: str) -> Any:
        try:
            return self._factories[name]()
        except KeyError as exc:
            raise LookupError(f"unknown component: {name}") from exc
```

```python
registry = Registry()
registry.register("email", EmailSender)
registry.register("lark", LarkSender)
sender = registry.create("lark")
```

Registry 可以保存：

- 已创建对象；
- 类；
- 工厂函数；
- 元数据或插件描述。

保存工厂通常比保存全局可变对象更容易控制生命周期。

## 适用场景

- 插件发现；
- 命令处理器映射；
- 序列化器、驱动和 Provider 注册；
- 框架启动阶段集中装配组件。

## Registry 与 Service Locator

| 用法 | 评价 |
|---|---|
| 应用启动时查询 Registry，再显式注入依赖 | 依赖仍然清晰，通常可接受 |
| 业务对象在任意位置调用全局 Registry 获取依赖 | 形成 Service Locator，依赖隐藏、测试困难 |

## 常见误区

- Registry 不是数据结构中的树；
- 不要求对象必须提前创建；
- 全局静态 Registry 会引入共享状态和测试污染；
- 注册冲突、作用域、生命周期和线程安全需要明确策略。

> [!tip] 面试回答
> Registry 是名称到组件的映射，适合插件和驱动发现；如果业务代码到处主动查全局 Registry，就会退化为 Service Locator。更好的做法是在应用入口解析后显式依赖注入。
