# 代理模式

> 代理模式提供与真实对象相同的接口，并在访问真实对象前后增加控制，例如鉴权、延迟加载、远程调用或缓存。

## 常见代理类型

| 类型 | 作用 | 示例 |
|---|---|---|
| 保护代理 | 权限控制 | 管理接口鉴权 |
| 虚拟代理 | 延迟创建昂贵对象 | 图片、模型、数据库元数据延迟加载 |
| 远程代理 | 代表远端对象 | RPC Client Stub |
| 缓存代理 | 避免重复调用 | API 缓存 |

## Python 示例：保护代理

```python
from typing import Protocol

class DocumentService(Protocol):
    def delete(self, document_id: str) -> None: ...

class RealDocumentService:
    def delete(self, document_id: str) -> None:
        print(f"deleted {document_id}")

class AuthorizedDocumentService:
    def __init__(self, target: DocumentService, role: str):
        self.target = target
        self.role = role

    def delete(self, document_id: str) -> None:
        if self.role != "admin":
            raise PermissionError("admin required")
        self.target.delete(document_id)
```

调用方只依赖 `DocumentService`，代理决定是否访问真实服务。

## 与相似模式区别

- **代理**：控制能否、何时、以什么方式访问真实对象；
- **装饰器**：为对象增加业务能力；
- **适配器**：改变接口；
- **外观**：简化整个子系统。

## 常见误区

- 缓存代理必须定义失效和一致性策略；
- 远程代理无法真正隐藏网络延迟、超时和失败，应在接口上表达这些差异；
- 代理层不应偷偷改变核心业务语义；
- Python 的动态代理若大量依赖 `__getattr__`，会降低类型检查能力。

> [!tip] 面试回答
> 代理和真实对象实现同一接口，主要目的是访问控制。它可以做远程调用、延迟加载、权限和缓存；与装饰器相比，结构相似但设计意图不同。
