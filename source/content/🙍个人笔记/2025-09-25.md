# 一、项目深挖（针对简历逐条核验）

1. **金融智能客服系统（2025.05–08）**
    
    - 你提到用 **LangGraph + GraphRAG + 多智能体 + Neo4j**，请画出从用户提问到最终回答的请求流（节点、状态、回退策略、缓存命中点）。
        
    - 预置 **100+ Cypher 模板** 的生成与维护如何做版本化与灰度？冲突或失败回退策略？
        
    - “多轮追问”触发的**可判定条件**有哪些？如何避免无休止追问（上限/置信度/拒答阈）？
        
    - **Map-Reduce 自我纠错 Cypher**：如何识别不一致？用什么指标/启发式判断“需要重试/修正”？
        
    - **性能数据**（响应时间-45%）：拆解主要优化项的占比（召回、重排、生成、外部 I/O）。
        
    - **评价点**：能说清状态机/边界条件/回退；对 Neo4j 查询与缓存有清晰拆分；有真实指标拆解。
        
2. **金融催收语音分流（2025.03–05）**
    
    - 39 类意图的数据增强策略与**数据泄漏**防范？混淆类意图如何系统性挖掘？
        
    - LoRA 三阶段微调（通用→混淆→多任务）各自目标、学习率/停早策略与过拟合监控？
        
    - **线上漂移**检测与再训练触发标准？
        
    - **评价点**：能把数据策划与训练闭环讲清，指标可复现实证。
        
3. **营销云智能洞察助手/数据服务化平台**
    
    - **DSL 生成与自纠错**如何落地（语法 vs 语义两个维度的校验）？
        
    - 指标口径统一 + 算子化的抽象边界？如何支持“临时口径”的灰度上线？

# 二、RAG / GraphRAG / 检索评估

1. **传统 RAG vs GraphRAG**：什么时候用图？图顶点/边如何从非结构化文档中抽取？抽取误差带来的**召回风险**怎么控？
    
    - 期待：清楚“图用于关系与约束推理”，承认抽取误差，提出“图+向量混检/重排”折中。
        
2. **分块策略**（CSV/PDF 自定义动态切分）：给出两种不同文档结构的切分规则，并说明对召回和重排的影响。
    
    - 期待：表格/章节/标题语义、页眉页脚过滤、跨页合并等细节。
        
3. **评估**：离线（NDCG / Recall@K / Faithfulness）+ 在线（点击/采纳/CSAT）；如何做**版本回放对比**？
    
    - 期待：能说 A/B、回放日志、统计显著性；误用单一指标的风险。
        
4. **重排器**：cross-encoder vs bi-encoder；在延迟预算下的**重排层数/层位**选择。
    
    - 期待：先召回→轻重排→重重排→生成，或预算受限时的折中。

# 三、LangGraph / 多智能体（Multi-Agent）

1. **LangGraph 状态机设计**：关键状态、边、记忆存储（memory/state channel）、失败重试策略（幂等/补偿）。
    
2. **多智能体协同**：规划-执行-验证-裁决（reflect/revise/route）。如何避免“回环”和“无效自言自语”（self-talk）？
    
3. **工具选择爆炸**：在 1000+ 工具下，如何**收敛候选**（语义检索/目录式发现/Router 策略），以及如何**控制 Token**？
    
4. **评价点**：能将“模型策略”与“系统约束”结合，落到可执行的图与限流/超时/并发控制。

2. **Nacos / Router / Klavis**：

# 实操题（任选其一，20–30 分钟）

**A. 设计题（白板/伪代码）**

> 为“金融智能客服”的**意图 → GraphRAG 检索 → 生成 → 追问**画 LangGraph 状态机：

- 节点：IntentDetect、KBSearch、KGQuery(Cypher)、AnswerCompose、Clarify、Finalize。
    
- 说明：每个节点的输入输出、失败重试、并行与缓存；给出两种触发 Clarify 的条件；在哪一层做流式输出。
    

**B. 代码题（可口述）**

> 给一个非结构化 PDF 的章节目录抽取+分块策略：

- 输入：PDF 文本（含标题、表格、图注）。
    
- 输出：分块列表（含 `title`, `level`, `text`, `anchors`）。
    
- 解释如何影响向量召回与重排；给出两处启发式规则与两处异常处理。
    

**评分要点**：结构化清晰、考虑异常与回退、权衡取舍与可观测性。

# 期望答案要点（速查）

- **GraphRAG 适用面**：强关系、实体对齐；用**混合检索**兜底；图构建误差→重排与拒答策略。
    
- **LangGraph**：显式状态与边；统一 `context`/memory；失败幂等；并行节点（工具/检索）。
    
- **Cypher 模板治理**：版本化、灰度、离线回放校验；模板 + few-shot 生成 + 语法/语义双校验。
    
- **Token 控制**：候选收敛（语义检索/目录式步进）、答案规划（思维压缩）、裁剪上下文。
    
- **LoRA**：小数据高效；rank/learning rate/正则；三阶段微调目的区分；早停与漂移监测。
    
- **SLA/观测**：QPS/P95、各阶段耗时、命中率、失败分布、召回/重排/生成的贡献度；可回放。
    
- **安全**：权限/审计/脱敏；工具最小权限；容器隔离（gVisor/Kata）；提示与数据水印。

# 红旗信号（可直接淘汰）

- 把 GraphRAG 当“更准”的万能钥匙，讲不清误差与兜底。
    
- 不理解 LangGraph 的**状态与边**，把它当“LangChain 的另一层封装”。
    
- 微调只谈参数，不谈**数据策划/线上漂移/回滚**。
    
- 对性能优化没有**阶段分解**与量化贡献。
    
- 工程视角薄弱：无鉴权/无限流/无日志与回放。
