## 一、系统概述

本系统旨在通过网关实现对前端发起的 API 请求进行统一鉴权，依托独立的 IAM（身份与访问管理）系统完成权限校验，确保只有具备相应权限的用户才能访问业务系统的 API 接口，保障系统的安全性和访问控制的有效性。

## 二、核心流程设计

### （一）流程概述

前端发起携带用户 Token 的 API 请求，经网关解析处理后，由 IAM 系统进行权限判断，根据鉴权结果决定是否将请求转发至业务系统，最终将处理结果返回给前端。

### （二）详细流程步骤

1. **前端发起请求**：前端向网关发起 API 请求，请求中携带用户 Token，用于标识用户身份。
    
2. **网关****解析处理**：网关接收到请求后，首先解析 Token 以获取用户标识，同时提取请求的 API 路径，为后续的鉴权操作准备必要信息。
    
3. **网关****请求获取权限**：网关将用户标识（user_id）发送至 IAM 系统，请求获取权限。
    
4. **IAM 返回相关权限**：IAM 系统接收到请求后，通过“用户→用户组→角色→权限→菜单→API ”的关联关系或“用户→角色→权限→菜单→API ”的关联关系获取权限API（第一次获取会放入缓存中，下次直接查询缓存），返回给网关。
    
5. **网关****鉴权**
    

网关拿到权限后，进行鉴权（根据API）。

6. **网关****鉴权结果处理**
    

- 若有权限，网关将 API 请求转发至对应的业务系统。业务系统处理业务逻辑后，将业务结果返回给网关，网关再将结果返回给前端。
    
- 若无权，网关直接向前端返回 403 权限不足的提示。

## 三、核心组件功能说明

### （一）前端

作为用户与系统交互的入口，负责发起 API 请求，并在请求中携带用户 Token，以表明用户身份。如H5、绝智APP、admin管理前端等。

### （二）网关

1. 接收前端发送的 API 请求。
    
2. 解析请求中的 Token，获取用户标识，用于确定请求来源的用户。
    
3. 提取请求的 API 路径，明确用户想要访问的具体接口。
    
4. 将用户标识发送至 IAM 系统获取权限相关信息，并进行鉴权。
    
5. 根据鉴权结果，决定是将请求转发至业务系统还是向前端返回权限不足的提示。
    
6. 在鉴权通过时，负责将业务系统返回的结果传递给前端。
    

### （三）IAM 系统

1. 接收网关发送的获取权限请求。
    
2. 基于“用户→用户组→角色→权限→菜单→API” 的关联关系或“用户→角色→权限→菜单→API ”的关联关系，获取用户相关权限信息。
    
3. 向网关返回权限信息，让网关进行鉴权。
    

### （四）业务系统

1. 接收网关转发的 API 请求。
    
2. 对请求进行业务逻辑处理，完成相应的业务操作。
    
3. 将处理后的业务结果返回给网关。
    

  

## 四、权限计算逻辑

1. 角色聚合：用户的有效角色 = 直接关联角色 ∪ 用户组关联角色
    
2. 权限提取：基于聚合后的角色集合，提取所有关联的权限
    
3. 菜单映射：将权限映射到关联的菜单
    
4. API 生成：将菜单映射到关联的 API，生成最终的权限列表
    

  

## 五、缓存策略设计

### （一）缓存结构

采用键值对存储：

- Key：user_id
    
- Value：API 路径列表（JSON 数组格式）
    

### （二）缓存过期策略

- TTL 设置：建议设置 30 分钟到 2 小时之间，根据业务变化频率调整
    
- 主动更新：当用户角色或权限发生变更时，主动刷新缓存
    
- 被动淘汰：当缓存空间不足时，自动淘汰最久未使用的数据
    

  

## 六、异常处理

当用户无权访问请求的 API 时，系统将通过网关向前端返回 403 权限不足的提示，使用户清晰了解无法访问的原因。
