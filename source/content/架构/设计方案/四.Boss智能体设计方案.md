#### 一、产品定位与核心价值

定位：基于飞书生态的“老板个人数字知识分身”。

核心价值：

    知识复用：将老板的会议记录（妙记）、文档批注转化为可检索的“第二大脑” ，模拟老板口语回复日常问题。

---

#### 二、系统架构设计

##### 2.1层级架构

采用经典的“接入层 - 核心服务层 - 数据层”三层架构，确保模块解耦，方便后期维护。

| 层级 | 组件 / 技术及描述 |
|-|-|
| **接入层** | ・飞书机器人：负责接收用户的文本（可扩展图片，文档链接），通过飞书事件订阅推送到后端  <br/>・飞书应用：作为前端入口，提供卡片交互界面 |
| **核心服务层** | ・Web 框架：使用 FastAPI 搭建，处理飞书的回调请求，提供异步高并发支持  <br/>・AI 编排：使用 Agno 框架，作为核心大脑负责意图识别、工具调用链的编排  <br/>・LLM：使用 Qwen-plus，相比 Max 版本在成本和速度上更优，适合处理长文本和日常对话 |
| **数据层** | ・向量数据库：使用 Qdrant，存储老板的知识库向量  <br/>・关系型数据库：使用 PostgreSQL，存储用户配置、对话历史、任务状态 |

#### 三、核心功能模块与实现逻辑

##### **知识库构建（RAG 流程）**

这是 “老板分身” 的基础，重点在于处理飞书特有的数据格式。

- **数据源**

  - 飞书妙记：调用飞书开放平台 API，定时拉取老板参与的会议记录。
  - 飞书云文档：同步老板创建或编辑过的文档。
  - 文档所在链接：[分身妙记](https://e0cmewvq7v7.feishu.cn/base/Se4Cb2ET6a6OJNscGRlcfMj4nDj?table=tblkNZNkNb9navVk&view=vewUK0c1eF)
- **数据处理**

  - 清洗：去除妙记中的口语废话、时间戳标记。
  - 切片：按段落或语义进行切分（Chunking），建议每块 500-800 token。飞书妙记按照提取发言切分
- **向量化**

  - 调用 `text-embedding-v4` 模型（1024 维）。该模型对中文语义理解极佳，适合企业内部黑话。
  - 存入 Qdrant，并带上元数据。

##### **智能问答引擎**

- **意图识别**

  - 用户提问 -> Agno 分析意图。
  - 分类：“查知识”（如：老板我们你上次说得顾家倒闭是怎么回事？）。
- **混合检索**

  - 如果是查知识，Agno 调用检索工具 -> Qdrant 进行向量检索 -> 召回 Top 5 相关片段。
  - 上下文增强：将召回的片段 + 用户问题 + 历史对话（PostgreSQL 读取）组装成 Prompt，投喂给 Qwen-plus。
- **回答生成** ：Qwen-plus 根据提示词人设生成最终回复。

##### **会话管理**

- **上下文管理**

  - 群聊：群内所有人将共享上下文信息（@机器人的文本才会被记录）
  - 个人：不同人员享个人记录
  - 储存：PostgreSQL 根据 session_id + user_id 确定唯一上下文详情

##### **记忆管理**

- 短期会话记忆：基于 PostgreSQL 存储当前会话的上下文窗口，确保多轮对话的连贯性（如追问 “他是指谁？” 时能关联上文）。
- 长期用户画像：利用 Agno 的持久化存储能力，从对话中自动提取用户的关键信息（如昵称、职位、偏好），构建动态更新的用户画像，实现个性化称呼与定制化回复。

##### **人设确定**

通过 “系统提示词注入” 与 “少样本学习” 确立分身基调。在 Agno 的 System Prompt 中定义核心人设（如：说话简练、幽默、喜欢用反问句），让模型在生成回复时进行风格模仿，避免 “机器味”，确保回复的口吻、用词习惯与老板本人高度一致。

##### **语音回复模块**

基于火山引擎 WebSocket 长连接构建低延迟语音合成链路，支持 “老板原声复刻”。通过上传老板的历史录音建立专属声音克隆模型，生成具有老板个人特色的音色标签。在回复时，系统根据内容重要性自动匹配该音色进行合成，将文本转化为高拟真的音频流，实现 “听声如见人” 的沉浸式交互体验。（目前只在飞书应用可以体验）

##### **语音识别**

基于腾讯云实时语音识别（Real-Time ASR）的 WebSocket 长连接构建，作为 Boss 智能体的 “听觉中枢”。该模块利用流式传输协议，将用户发送的飞书语音消息实时转写为文本流，具备端点检测能力，能自动判断语音结束并截断。

#### 四.接口服务

##### 1. `routes/asr.py` — 语音识别接口

**功能**：接收音频文件 / 音频流，将语音转换为文本，为后续对话提供文本输入。

- 典型场景：飞书语音消息 → 转文本 → 传入 `chat.py` 处理
- 主要接口：

  - `POST /api/asr/token`：上传音频文件，返回识别后的文本内容
  - 支持格式：常见音频格式（如 MP3、WAV、M4A）

---

##### 2. `routes/auth.py` — 鉴权接口

**功能**：处理飞书应用 / 机器人的身份验证、签名校验、权限控制，确保接口调用安全。

- 典型场景：飞书事件回调签名验证、用户身份鉴权
- 主要接口：

  - `GET /feishu/callback`：验证飞书请求签名合法性

---

##### 3. `routes/chat.py` — 对话核心接口

**功能**：对接 RAG 系统，接收用户提问，完成知识检索与大模型生成，返回最终回答。

- 典型场景：飞书用户提问 → 本接口 → 调用 RAG → 返回答案
- 主要接口：

  - `POST /api/chat/stream`：接收用户问题，返回流式回答
  - 内部流程：
  
    1. 接收飞书消息
    2. 参数校验与用户身份识别
    3. 调用 RAG 系统进行知识库检索
    4. 融合提示词与检索内容
    5. 调用大模型生成回复
    6. 返回结果给飞书

---

##### 4. `routes/health.py` — 健康检查接口

**功能**：提供服务存活、依赖状态检查，用于监控与运维。

- 典型场景：K8s 存活探针、服务状态巡检
- 主要接口：

  - `GET /health`：返回服务运行状态（200 OK 表示正常）

---

##### 5. `routes/tts.py` — 语音合成接口

**功能**：将文本转换为语音，用于语音形式的回复输出。

- 典型场景：对话回答文本 → 转语音 → 飞书语音消息回复
- 主要接口：

  - `POST /api/tts`：接收文本，返回音频流 / 音频文件下载链接
  - 支持格式：常见音频格式（如 MP3、WAV）

#### 五.开发指南

##### 4.1 环境要求

- Python 3.12+
- PostgreSQL 14+

```SQL
CREATE TABLE public.user_bindings (
    -- 你系统的用户ID（主键）
    internal_user_id VARCHAR(64) PRIMARY KEY,
    
    -- 飞书关键字段（唯一约束）
    feishu_open_id VARCHAR(64) UNIQUE NOT NULL,  -- 全局唯一
    tenant_key VARCHAR(64) NOT NULL,             -- 企业标识
    
    name TEXT,
    avatar_url TEXT,
    
    -- 时间戳
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

##### 4.2 快速开始

```Bash
# 1. 克隆项目

cd boss_agent

# 2. 安装依赖
poetry install

# 3. 配置环境变量
cp .env.example .env
vim .env  # 修改配置

# 4. 启动服务
poetry run python main.py
```
