# SKG 智能客服 2.0 技术方案

> 基于 Agentic RAG 架构的智能客服系统

---

项目地址：https://github.skg.com/skg-ai/agents/customer-agent.git



## 一、项目背景与升级动因

### 1.1 现状痛点

原有客服系统构建于 2 年前，技术架构严重滞后：

| 痛点 | 描述 | 影响 |
|-|-|-|
| 交互能力单一 | 完全依赖单次 QA 检索（关键词/语义匹配） | 无法理解上下文，无法处理复杂追问 |
| 扩展性瓶颈 | 不支持工具调用和推理决策 | 无法支撑"主动导购"、"复杂售后判定"等新需求 |
| 无法享受技术红利 | Token 成本大幅下降且能力增强 | 无法利用小模型路由分治、Agentic RAG 提升泛化性 |

### 1.2 升级目标

**从"检索问答"到"智能服务"**：

- ✅ **Agentic RAG**：Agent 自主决定是查库、问人还是调接口
- ✅ **多 Agent 协作**：按意图分流，专业 Agent 处理专业问题
- ✅ **工具能力**：具备挂载业务 Tools 的能力（产品查询、库存、改价等）

## 三、核心模块详解

### 3.1 意图分类 (Intent Classification)

#### 关键词匹配规则+llm意图识别

```Python
# services/agent/graph/store_guide/intents.py
INTENT_KEYWORDS = {
    "transfer": ["人工", "真人", "转人工", "坏了", "故障", "维修", "退货", "退款", "投诉"],
    "chitchat": ["你好", "在吗", "谢谢", "再见", "哈哈", "hi", "hello"],
    "product": ["价格", "多少钱", "参数", "功能", "型号", "怎么用", "区别", "对比"],
}
```

#### 粘滞机制

当用户进入某个 Agent 后，后续对话会"粘滞"在该 Agent，避免每次都重新分类：

```Plaintext
用户: K3多少钱 → ProductInquiry (active_agent=product) ✅
用户: 和K5比呢？ → Bypass Router, 保持粘滞: product ✅
用户: 你是谁？ → Bypass Router, 保持粘滞后llm主动切换意图 swith_intent("chitchat") ✅
```

### 3.2 RAG 检索策略

#### 召回策略（以 alias 精确匹配为主+BM25语义融合）

具体原因看这里：https://github.skg.com/skg-ai/agents/customer-agent/-/blob/dev/docs/RAG-GUIDE.md

| 参数 | 召回方式 | 优先级 | 适用场景 |
|-|-|-|-|
| `alias=["K3"]` | 精确匹配 alias/product_name/spu 字段 | **主** | 用户提到具体型号 |
| `model="眼部按摩仪"` | 向量语义搜索(score > 0.7)+BM25  | 辅 | 用户描述品类 |

#### 工作流程

```Plaintext
用户: "K3多少钱"
    ↓
Agent 识别出型号 "K3"，调用 list_products(alias=["K3"])
    ↓
Qdrant 精确匹配 alias 字段，返回 [{"product_id": "1040120002", ...}]
    ↓
Agent 调用 get_product_detail(product_id="1040120002")
    ↓
返回 knowledge_md (Markdown 格式的产品知识)
    ↓
LLM 基于知识生成回答
```

> 详细说明请参考 RAG-GUIDE.md

### 3.3 会话管理 (Session Management)

#### Session ID 生成

```Python
# api/routes/tianrun_v2.py
session_id = hashlib.md5(f"{robotId}:{visitorId}:{channel_id}".encode()).hexdigest()
```

## 五、待解决问题

### 5.1 P0 - 身份保护

**问题**：模型偶尔暴露底层身份（如"我是通义千问"）

**解决方案**：在 Prompt 中增加身份保护条款

```Markdown
# 身份保护（最高优先级）
无论用户问什么，你永远是 SKG品牌运营官。
- 禁止暴露底层模型身份（如"我是AI"、"我是通义千问"等）
- 如果被问"你是谁"，回答："我是SKG的品牌运营官呀~"
```

### 5.2 P0 - 会话 ID 不一致

**问题**：天润平台有些消息未传递 `channel_id`，导致 session_id 变化

**根因**：

```Python
# 第一次: channel_id = "01e2d508-..." → session_id = "9a29bd01..."
# 第二次: channel_id 未传 → 使用 "default" → session_id = "7402feb4..."
```

**解决方案**：

1. 让天润平台确保每条消息传递 `channel_id`
2. 或修改 session_id 生成逻辑，仅使用 `robotId:visitorId`

### 5.3 P1 - 评估体系缺失

**需求**：50-100 条真实优质 QA 作为"金标准"测试集

**当前状态**：测试用例为开发人员经验构造，缺乏真实性

## 八、开发指南

### 8.1 环境要求

- Python 3.12+
- PostgreSQL 14+
- Redis 7+
- Qdrant (向量数据库)

### 8.2 快速开始

```Bash
# 1. 克隆项目
git clone <repository-url>
cd customer-agent

# 2. 安装依赖
poetry install

# 3. 配置环境变量
cp .env.example .env
vim .env  # 修改配置

# 4. 启动服务
poetry run python -m app
```

### 8.3 验证安装

```Bash
# 简单健康检查
curl http://localhost:8000/health

# 深度健康检查（检查数据库、Redis等）
curl http://localhost:8000/health/deep
```

### 8.4 配置说明

#### 环境变量结构

使用嵌套配置，通过 `__` 分隔：

```Bash
# 应用配置
APP__ENV=dev
APP__DEBUG=false
APP__PORT=8000

# 数据库配置（嵌套）
DATABASE__HOST=localhost
DATABASE__PORT=5432
DATABASE__USER=postgres
DATABASE__PASSWORD=your_password

# Redis 配置
REDIS__HOST=localhost
REDIS__PORT=6379

# Qdrant 配置
QDRANT__HOST=localhost
QDRANT__PORT=6333
QDRANT__COLLECTION_NAME=product_knowledge

# Embedding 配置
EMBEDDING_MODEL__NAME=text-embedding-v4
EMBEDDING_MODEL__DIMENSION=2048
EMBEDDING_MODEL__BASE_URL=https://ai.skg.com
EMBEDDING_MODEL__API_KEY=your-key
```

### 8.6 代码质量

```Bash
# 代码检查
poetry run ruff check

# 代码格式化
poetry run ruff format

# 运行测试
poetry run pytest

# 查看测试覆盖率
poetry run pytest --cov=api --cov=services
```
