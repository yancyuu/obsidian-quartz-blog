
### 一、AI 应用机制理解类问题

#### 1. **RAG 机制中模型“复读机”现象的成因与解决思路？**

**目的：** 判断其是否理解RAG流程、Prompt组装与Retriever之间的耦合影响  
**期待答案方向：**

- 检索结果未过滤重复实体或chunk粒度太粗
    
- Prompt组装方式（如直接拼接 vs 抽象总结）
    
- Retriever权重设置或向量表达存在重复偏移
    
- 解决方案：去重、摘要生成、引入Re-ranker、Prompt模板优化等
    

#### 2. **向量召回时，Milvus 或 Faiss 为何会返回一些“看似不相关”的结果？怎么排查？**

**目的：** 判断其对相似度计算机制的理解  
**期待答案方向：**

- 使用的距离度量方式（cosine vs L2）不合理
    
- Embedding 模型本身语义不精确或不对齐
    
- 向量标准化错误、维度不一致
    
- 排查方式：人工验证top-k结果，查看embedding分布、增加内容索引标签过滤等
    

#### 3. **使用知识库驱动大模型问答时，知识更新和版本一致性如何保障？**

**目的：** 考察其对知识库架构设计的思考  
**期待方向：**

- 向量库和结构化元数据同步机制设计（如写操作绑定版本号）
    
- 文档切割与向量更新过程的幂等控制
    
- 异步索引机制、全文本存储与版本快照管理

### 💡 二、系统架构与性能问题

#### 4. **在高并发向量查询场景中，如何防止 Milvus 查询性能下降甚至 OOM？**

**目的：** 判断其对 Milvus 运维和查询优化的理解  
**期待方向：**

- 控制并发请求数、使用 token bucket 限流
    
- 控制查询超时、分页返回
    
- 使用 IVF_FLAT / HNSW 等索引类型的选择与评估
    
- 启用 hybrid search 结合结构化查询前过滤
    

#### 5. **多用户多租户下知识库检索如何做权限隔离？**

**目的：** 判断其对 ACL 设计和知识库多租户系统的理解  
**期待方向：**

- 结构化部分设置字段级 ACL（如 Casbin 或代码内 Role 分级）
    
- 向量查询通过知识库前缀（collection分组）控制隔离
    
- 使用领域（Domain）作为检索条件嵌入 embedding 检索请求中

### 💡 三、Agent 与 LLM 集成问题

#### 6. **大模型配合知识库问答时，多轮对话信息如何保留并准确驱动检索？**

**目的：** 判断其对 Agent 状态管理和 context 构建理解  
**期待方向：**

- 使用 memory 保存历史 Q/A
    
- 使用 recent turns 构造 user profile / 意图
    
- 对话中的实体提取后构造 query
    
- 检索依赖动态 slot 填充 / query 改写 / prompt chain 等
    

#### 7. **如何在 Agent 编排中实现任务粒度控制与错误回滚？**

**目的：** 判断其对多步骤流程控制的理解  
**期待方向：**

- 使用 Task DAG 或状态机（如LangGraph）
    
- 设置每步结果验证机制（Output Validator）
    
- 出错时触发补偿逻辑或进入“手动干预”队列
    
- 记录流程日志与中间状态便于追踪
